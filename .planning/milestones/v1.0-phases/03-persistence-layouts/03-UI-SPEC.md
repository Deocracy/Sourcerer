# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 3 is almost entirely non-visual (persistence plumbing — PERS-01/03/04). The only net-new UI surface is the **LAYOUTS ▾** title-bar dropdown (PERS-02) and its one companion element, the **corrupt-reset notice** (D-04). This spec covers those two surfaces only; everything else in this phase touches zero pixels. No shadcn, no component library — the project is explicitly bespoke CSS Modules + `tokens.css` (CLAUDE.md "What NOT to Use").

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (dropdown trigger) | `LAYOUTS ▾` (existing D-01 locked label, mono, matches `DIVI` chip casing convention) |
| Primary CTA (save action, inside dropdown) | `Save current…` (D-01 locked label — ellipsis signals it opens a name-input, not an instant save) |
| Reset action | `Reset` (D-01 locked label) |
| Empty state heading | none (no heading — dropdown is a flat list, not a page) |
| Empty state body | `No saved layouts yet` — shown in the dropdown list area when zero named layouts exist, above the `Save current…` row, 13px sans, `--color-muted` |
| Delete confirmation (destructive) | Per-row delete: no modal — hover reveals a small "×" glyph; clicking it deletes immediately (single-level list item, low-cost/reversible-by-resave action, consistent with the rest of the shell's no-modal interaction language e.g. rail pin toggle). If the checker requires an explicit confirm step, use an inline two-click pattern: first click turns the "×" into "Delete?" for ~2s, second click within that window deletes; no click elsewhere cancels it. |
| Corrupt/stale fallback notice (D-04) | `Workspace was reset after a problem loading your layout.` — single line, 13px sans, `--color-fg-secondary`, dismissible via an inline "×" (same glyph language as the delete affordance), non-blocking, auto-positioned as a small inline banner (not a toast stack — the shell has no toast system, this is the one self-contained exception per D-04) |
| Save-current name prompt | Inline text input, placeholder `Layout name…`, confirm on Enter, cancel on Escape — no separate modal dialog (matches the shell's flat, modal-free interaction language) |

## Interaction Contract (LAYOUTS dropdown — net-new, no design-handoff precedent)

Since the `bespoke_rails_shell` handoff has no layouts-menu reference (confirmed in 03-CONTEXT.md — "the prototype only ever did the single auto-saved dockview layout"), this section locks the interaction pattern by extension from the shell's existing chrome language (DiviChip toggle-button, rail pin hover-reveal, WindowControls hover-color-shift):

- **Trigger:** `LAYOUTS ▾` sits in the title-bar right cluster, positioned before the two `RailToggleButtons` SVG icons (D-01). Styled as a text button matching `DiviChip`'s chip treatment (mono label, 1px border, `--color-line` default / `--color-accent` on hover-or-open) rather than an icon button — it carries a text label, unlike the rail toggles.
- **Panel:** Opens downward, right-aligned to the trigger, `--color-bg` background, 1px `--color-line` border, `0` border-radius (project-wide radius-0 rule holds — the dropdown is NOT an exception the way the outer window card is). Min-width matches trigger, max-width ~280px, row height 36px (`--rail-row-h`).
- **Row anatomy (each saved layout):** label (13px sans, truncates with ellipsis past max-width) + right-aligned hover-revealed delete "×". Active/applied layout gets the accent-colored left border (2px, matching `--rail-active-border`) and accent label color — same visual grammar as the rail's active-item indicator.
- **List order:** most-recently-saved first, OR alphabetical — Claude's Discretion per 03-CONTEXT.md; default to most-recently-saved-first (matches typical "recent items" expectation, no research contradicts it).
- **Footer rows:** `Save current…` and `Reset` render below a 1px divider under the layout list, in `--color-faint` unless hovered (hover → `--color-fg`), no accent (they are neutral utility actions, not the active-state indicator).
- **Dismiss:** click-outside, Escape, or re-clicking the trigger closes the dropdown. No animation requirement beyond the project's implicit instant-toggle language (DiviChip, rail toggles have no transition — match that, don't invent an easing curve).
- **Keyboard:** Arrow-up/down moves focus between rows (focus ring = 1px accent outline); Enter applies the focused layout; Delete/Backspace on a focused row triggers the same two-click-confirm delete as pointer hover.
