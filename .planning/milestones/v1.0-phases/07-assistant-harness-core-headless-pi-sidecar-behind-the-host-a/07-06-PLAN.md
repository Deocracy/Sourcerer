<objective>
Close GAP-07-D09: chat history does not reload/render on app restart. The file-backed
persistence engine (07-02, JSONL sessions) is proven correct — the gap is purely
frontend/protocol: the panel mints a fresh sessionId every mount and there is no protocol
path to fetch prior turns for display. This plan adds a load/replay path across all four
layers (protocol -> sidecar -> Rust -> panel) and persists the sessionId across restarts.

Purpose: deliver the D-09 observable truth the user explicitly wanted — "the current
session's turns render on open, so history survives restart."
Output: a `loadSession` request + `history` event on the stdio contract; a `load_session`
Tauri command; a `host.loadSession()` seam; a persisted sessionId and an on-mount reload in
AssistantPanel; a sidecar replay unit test and a frontend reload-history test.
</objective>

Sidecar stdio contract (sidecar/src/protocol.ts, existing):
- Requests: PromptRequest {type:"prompt",id,sessionId,message,modes[]} | SetModesRequest {type:"setModes",modes[]}. Union `SidecarRequest`. `isSidecarRequest()` type-guards each variant; malformed lines are skipped in readRequests().
- Events (one JSON/line on stdout): ready | thinking_delta | text_delta{id,text} | tool_start | tool_end | error{id,message} | done{id}. Union `SidecarEvent`. writeEvent(evt) serializes one line.

File-backed sessions (sidecar/src/sessions.ts, existing, proven by sidecar/test/sessions.test.mjs):
- `class FileSessionManager` — `open(sessionId): Promise<SessionManager>` (creates or resumes), `listSessionIds(): Promise<string[]>`, `getSessionDir()`.
- `isValidSessionId(id)` guards SESSION_ID_PATTERN `/^[A-Za-z0-9](?:[A-Za-z0-9._-]*[A-Za-z0-9])?$/` (no "..").
- SessionManager (from @earendil-works/pi-coding-agent) exposes `getEntries(): SessionEntry[]`. Message entries have `entry.type === "message"` with `entry.message.role` ("user"|"assistant") and `entry.message.content` — a **string** for user turns, an **array** `[{type:"text",text}, ...]` for assistant turns (see appendTurn() in sessions.test.mjs).

Sidecar loop (sidecar/src/index.ts, existing):
- Module-level `let fileSessionManager: FileSessionManager | null` (lazily `new FileSessionManager(cwd)` where `cwd = __dirname`).
- `handleRequest(req)` branches on req.type ("prompt" -> getOrCreateSession + setModes + runPrompt; "setModes" -> setModes). `main()` emits ready then iterates readRequests().

Rust relay (src-tauri/src/commands/ai.rs + sidecar.rs, existing):
- `host_ai(message, session_id, modes, on_event: Channel<Value>, sidecar)` — mints `fresh_request_id()`, `sidecar.register(&id)` -> rx, `sidecar.write_line(prompt.to_string())`, then loops relaying every rx event to `on_event.send()` until type=="done" (TURN_TIMEOUT guard). `send_degrade(&on_event,&id,msg)` emits exactly one error + one done and returns Ok on any failure.
- SidecarProcess exposes register(&id)->rx, unregister(&id), write_line(&str)->Result. pump_stdout dispatches events by their `id` field to the registered listener.
- lib.rs registers commands via `.invoke_handler(tauri::generate_handler![commands::ai::host_ai, commands::ai::set_modes])`.

Frontend seam (src/host/ai.ts, existing):
- `ai(request,onEvent): Promise<void>` — new `Channel<AssistantEvent>()`, invoke("host_ai",{message,sessionId,modes,onEvent:channel}), resolves on "done", and on invoke-reject delivers an error+done pair to onEvent (never throws). `setModes(modes)` invokes "set_modes". Exported `host = { ai, setModes }`. AssistantEvent union mirrors the seven sidecar shapes.

Panel (src/assistant/AssistantPanel.tsx, existing):
- `const newSessionId = customAlphabet("0123456789abcdefghijklmnopqrstuvwxyz", 21)` (alphanumeric-only, CR-01). Currently `const sessionId = useRef(newSessionId())` — THE BUG: fresh id every mount, never persisted, never reopened.
- Chat state is local: `messages: ChatMessage[]` ({id,role,text,status,toolNotice?}). onEvent switch handles text_delta/tool_start/tool_end/error/done; ready+thinking_delta suppressed. Reaches AI only through `host.ai()`/`host.setModes()`.

Test harnesses:
- Frontend: src/assistant/AssistantPanel.test.tsx uses mockIPC from @tauri-apps/api/mocks; `deliver(onEvent, events[])` calls `onEvent.onmessage(event)` on microtasks. Vitest environment is jsdom (localStorage available).
- Sidecar: sidecar/test/sessions.test.mjs uses node:test; `appendTurn(sm,text)` appends a user + assistant message; `sm.getEntries()` round-trips across a fresh FileSessionManager. Test script in sidecar/package.json runs an explicit file list under `node --experimental-strip-types --test`.
