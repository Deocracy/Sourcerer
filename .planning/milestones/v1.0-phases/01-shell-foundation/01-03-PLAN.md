<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: Verify frameless window + title bar + controls + drag (SHELL-01/02/04 real behavior)</name>
  <files>none — verification-only, no files modified</files>
  <what-built>
    A frameless Tauri window with a 34px custom title bar (logo + "Sourcerer" + "·" + "Home" crumb in bundled IBM Plex Mono, left), a drag-spacer, and minimize/maximize/close controls wired to the Tauri window API. Automated specs already confirm structure, command wiring, and local-only fonts; this confirms the real OS behavior jsdom cannot.
  </what-built>
  <how-to-verify>
    1. Run `npm run tauri dev` and wait for the window to appear.
    2. Confirm the window is frameless: no native OS title bar/menu, and — critically — NO faint white hairline outside the intended #1E1F22 border and NO rounded outer corners (the shadow:false check; Win11 auto-round). If you see either, shadow was not disabled.
    3. Confirm the title bar: 34px tall, "Sourcerer" wordmark + "Home" crumb rendered in IBM Plex Mono (not a system/serif fallback), logo mark visible, 1px bottom border.
    4. Click Minimize — window minimizes. Restore it from the taskbar.
    5. Click Maximize — window maximizes and the button's icon/tooltip flips to "Restore window". Click again — it restores and the label flips back. Also double-click the title-bar spacer to maximize and confirm the icon still tracks correctly (state, not click-toggle).
    6. Click Close — window closes. Relaunch for the next steps.
    7. Drag the window by the empty spacer area between the crumb and the controls — the window moves. Now try to "drag" by clicking a control button and the logo cluster — these must NOT move the window; the buttons fire their action, the logo fires its openHome stub. No button swallows a click.
    8. (Optional) Open devtools Network tab and confirm zero requests to fonts.googleapis.com / fonts.gstatic.com.
  </how-to-verify>
  <action>Launch the built shell via `npm run tauri dev` and walk the user through the how-to-verify steps; collect an approval or a defect list. Any defect routes back to plan 01-01 (config: shadow/decorations/capability) or 01-02 (component behavior) for a fix before the phase closes. This task performs no code changes.</action>
  <verify><human-check>User confirms steps 1-8 pass: frameless render, no white border / rounded corners, controls perform real OS operations, maximize icon tracks real state, drag on spacer only, no click swallowing, local-only fonts.</human-check></verify>
  <done>User types "approved" for all steps, or defects are logged and routed back to the owning plan (01-01/01-02).</done>
  <resume-signal>Type "approved" if all steps pass, or list the steps that failed (e.g. "step 2: white border visible" / "step 7: minimize button starts a drag").</resume-signal>
</task>

  </what-built>
  <how-to-verify>

    3. Confirm the title bar stays ~34px logical (proportion looks correct, text not clipped, controls not misaligned).
    4. Confirm no visible blur on the wordmark/crumb text or the logo ring.
    Take a screenshot at each scale factor for the record if convenient.
