<objective>
Prove the entire `@sourcerer/*` extension mechanism end-to-end with one thin
production-quality vertical slice: a real `@sourcerer/branding` package that
lives in a new `extensions/*` workspace, compiles with `tsc -b`, is discovered
by `theia build` through `theiaExtensions`, loads a `ContainerModule` into the
frontend DI container, and mutates the running page — verified in a headless
browser, not by reading source.

Purpose: this is the phase's highest architectural risk concentrated into one
commit. If workspace discovery, `theiaExtensions` resolution, the direct-
dependency requirement (D-31), or the `theia.frontend.config` custom-key path
(D-62) is wrong, it is wrong here, after one commit, not after six.

Output: a working branded title + favicon in the standalone app,
`scripts/lib/firefox-bidi.mjs` — the shared headless driver every later check
script imports — and `scripts/verify-branding.mjs`, its first consumer.

**Shared-driver ownership, decided and recorded:** `02-VALIDATION.md` lists
`scripts/lib/firefox-bidi.mjs` as a Wave 0 item, and Plan 02 is the plan that
carries the rest of Wave 0. It is nevertheless created **here**, in Wave 1,
because this plan's own `<verify>` runs a BiDi assertion — a Wave 1 plan cannot
depend on a file a Wave 2 plan creates, and the alternative (write a
self-contained launcher here, refactor it onto the shared lib in Plan 02) is
strictly more work for the same end state. Plan 02 consumes it and extends it
with the screenshot helper Plan 05 needs; Plans 03 and 05 import it unchanged.
</objective>
