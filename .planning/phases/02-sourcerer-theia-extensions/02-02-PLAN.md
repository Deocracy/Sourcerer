    Write `scripts/verify-dev-flag-off.mjs`, a plain Node ESM script taking the
    app URL from `argv[2]` (default `http://localhost:3000`) and an optional
    `--expect-bound` flag.

    Default mode asserts the binding is ABSENT: launch headless chromium via
    `playwright`, `goto` the URL, `waitForFunction` on `window.theia?.container`,
    then `page.evaluate` a callback that calls
    `Symbol.for('SourcererPrivilegedJs')` and passes the result to
    `window.theia.container.isBound(...)`. Exit 0 with
    `verify-dev-flag-off: PASS` when the result is `false`; exit 1 with
    `verify-dev-flag-off: FAIL -- SourcererPrivilegedJs is bound with the dev
    flag off` when it is `true`.

    `--expect-bound` inverts the assertion. This is the positive control the
    Assumptions Log demands: the whole mechanism rests on a `Symbol.for` key
    resolving to the same symbol inside `page.evaluate` as inside the bundle,
    and a script that structurally can only ever report "not bound" would pass
    against an app that never defined the token at all. Plan 05 runs both modes.

    Put a header comment in the file stating the two vacuous-pass modes and how
    this script avoids each: it must be pointed at an app started from a
    `theia build` artifact (the backend prefers `lib/backend/main.js` and serves
    `lib/frontend`, so hand-edited `src-gen` changes nothing), and it evaluates
    in the page rather than grepping source. Also record D-65's caveat: this
    asserts binding absence, not artifact absence — the class remains in
    `bundle.js` because tree-shaking cannot remove code behind a runtime config
    read, and CUST-02 as worded requires the former.

    Note the current expected state: with `@sourcerer/customize` not yet built
    (Plan 05), the token is never registered, so default mode returns `false`
    and passes for the wrong reason. That is exactly why `--expect-bound` exists
    and why Plan 05 must run it.
  </action>
