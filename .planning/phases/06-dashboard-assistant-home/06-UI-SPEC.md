| Role | Size | Weight | Line Height |
|------|------|--------|-------------|

| Display | 12px (`--fs-display`) | 400 | 1 |

**Phase 6 additions — this phase's content system is a dense information-dashboard aesthetic
(same family already established in the Phase 4 Wiki/Library demo stubs). Declare these as
named exceptions to the 4-size base scale, scoped strictly to assistant/Home surfaces:**

| Named role | Size | Family | Weight | Line height | Usage |
|---|---|---|---|---|---|
| `asst-body` | 13px | Sans | 400 | 1.55 | Thread message text, composer input |
| `asst-label-mono` | 11px | Mono | 500 | 1, letter-spacing 0.14–0.18em, uppercase | Model/effort picker text, `[y] approve` / `[d] diff` / `[n] reject` action row, "LET GO TO SNAP" resize cue, section headers ("◆ PINNED", "FRESH", "LIVING", "ARCHIVE") |
| `proposal-quote` | 14px | Serif italic | 400 | 1.5 | The accepted/pending proposal quote block (serif-italic per ASST-02) |
| `card-title` | 15px | Serif | 400 | 1.15 | Home card title text |
| `living-quote` | 19px | Serif italic | 400 | 1.2 | LIVING section question card |
| `card-micro` | 8–10px | Mono | 400–500 | 1, letter-spacing 0.14em | Card `kind` tag, foot/metadata row, timestamps — dense metadata only, never primary UI chrome |

Rationale for the wider size set: this is a data-dense card/dashboard system (established
precedent in Phase 4's Wiki/Library rich demos), not a marketing surface — the checker's
"3–4 sizes" default is extended here deliberately per the handoff's own type system, not
arbitrary drift. Keep every new size traceable to `home-cards.js`/`dc.html` — do not invent
additional sizes beyond this table.

## Color

Inherited from `tokens.css` — no new colors, only new usage assignments for this phase:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0A0B` (`--color-bg`) | Home dashboard background, assistant closed-strip background |
| Secondary (30%) | `#131418` (`--color-panel`) assistant aside surface; `#1A1B1E`/`#1E1F22` Home card surfaces | Assistant panel background, message bubbles, Home card fills |
| Accent (10%) | `#86A38C` (`--color-accent`), hover `#A3BCA8` | See explicit reserved-for list below |
| Destructive | `#C42B1C` (`--color-danger`) | **Not used in Phase 6** — see note below |

**Accent reserved for (explicit list — do not extend beyond this):**
- Send button enabled/active background (composer)
- Model-picker diamond glyph (◈) and its "current model" checkmark
- Live-session pulse dot markers (`mark:'live'` cards, active-session indicators)
- Home card progress-bar fill (ingestion progress variant) and metric up-arrow (▲)
- The **＋ MAKE CARD** action affordance (primary CTA, D-06)
- `[y] approve` proposal action hover/active state (the accept path only — not `[d]`/`[n]`)

**Destructive color: not used this phase.** Per D-02/dc.html, `reject` (`[n]`) renders in muted
gray (`#A5A29A`→`#E6E4DE` hover), not red — rejecting a proposal is a reversible, non-destructive
action, and closing a session chip does not delete its JSONL history (Phase 7 D-06). `--color-danger`
stays reserved for its existing Phase 1/2 role (window close button) and must not be reused here.

## Interaction Notes (non-visual contract, still binding)

- **ASST-01 sessions:** session list = real Pi sessions (live `host.ai()`, reopened JSONL) +
  seeded read-only staged transcripts (D-01). Selecting a seed shows a canned transcript with
  composer disabled/hidden for that session (no live send).
- **ASST-02 proposals:** client-side pattern-matched from streamed text (D-02) — no new
  `host.ai()` event shape. Rendered as the `proposal-quote` block above with `[y] approve /
  [d] diff / [n] reject`; keyboard `y`/`d`/`n` act on the currently-focused proposal only.
  Accepting (`y`) is the trigger that offers ＋ MAKE CARD.
- **ASST-03 resize:** reuse `railSnap.ts`/`useRailDrag.ts` bespoke pointer pattern (D-03) — grip
  on the panel's left edge (`--asst-resize-handle-w`), drag-in closes to `--asst-closed-w`,
  drag-out past a snap threshold expands to fullscreen, "LET GO TO SNAP" cue (`asst-label-mono`
  role) shown during the snap zone per dc.html line 90. Width persists via a new shell-store
  slice (`asstWidth`/`assistantOpen`) — **note for planner: this slice does not yet exist in
  `src/store/shellStore.ts`** (confirmed by source read 2026-07-14); it must be added this phase,
  it is not a pre-existing seam to merely wire into.
- **HOME-01 visibility:** Home is both the empty-dock default AND summonable via `DiviChip`
  `toggleDivi` / `LogoCluster` `openHome` (currently no-op stubs — replace their handlers, per
  D-04). Renders as an overlay per dc.html's `diviOpen` pattern (`position:absolute; inset:0;
  z-index:55`), not a plain dock panel.
- **HOME-02 cards:** dnd-kit `DndContext` + `SortableContext` (rectSortingStrategy), FLIP via
  dnd-kit's built-in transform/transition (no separate FLIP library). Card `cardDefs` content
  stays the curated demo registry (`home-cards.js`); only section membership + order persist via
  `host.storage` (D-05), replacing the reference's raw `localStorage['sourcerer-home-cards-v2']`.
  ARCHIVE section supports a cards/list view toggle (◧ CARDS / ≡ LIST); LIVING section renders as
  a single wide block, not a grid cell.
