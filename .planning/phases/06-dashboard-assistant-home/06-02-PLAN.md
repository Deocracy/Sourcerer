<objective>
## Phase Goal

**As a** scholar using the Dashboard Assistant, **I want to** see a list of my conversations —
real live sessions alongside a couple of lived-in demo transcripts — and switch between them,
start a new one, and send a message that streams back a reply, **so that** the assistant feels
like a real multi-session workspace, not a single ephemeral chat box.

Grow (do NOT replace) the shipped Phase 7 `AssistantPanel.tsx` from its single-session form into a
multi-session panel: a session list (real + seeded read-only transcripts per D-01), an active
session selector, and the handoff's header chrome (history / new-session icons, model picker as a
demo affordance). The existing `host.ai()` streaming, sessionId minting (CR-01 alphanumeric
alphabet), and `host.loadSession` history replay are reused verbatim, generalized from one
`useRef` sessionId to a list-backed selection. This plan also lands the full `--asst-*` token block
in `tokens.css` (consumed by Plans 06-03/06-04 too), so no later assistant plan touches tokens.css.

Purpose: deliver ASST-01 (session list, thread, composer, ⌘↵ send, stubbed/streamed replies).
Output: grown `AssistantPanel.tsx`, new `sessionSeeds.ts`, `--asst-*` tokens, extended tests.

| T-06-02-01 | Injection (XSS) | Streamed/seed text rendered in the thread | mitigate | Render as React text children only — no dangerouslySetInnerHTML anywhere in the panel |
