(they spawn the Node backend). Each check starts the sidecar itself via a shared

`start_backend` contract: generate a random token into a shell variable, then run
the pinned Node binary against `theia/applications/browser/lib/backend/main.js`
with argv `--hostname 127.0.0.1 --port 0` and environment carrying
`SOURCERER_TOKEN=<token>`, `THEIA_CONFIG_DIR="${XDG_CONFIG_HOME:-$HOME/.config}/sourcerer"`
and `VSX_REGISTRY_URL=https://open-vsx.org`, launched under `setsid` with stdout and
stderr redirected to a `track_temp`-registered log file. Poll that log file for the
line beginning `SOURCERER_BACKEND_READY` and parse the JSON that follows it to get
the port and the backend pid. Fail the check with a clear message if the sentinel
does not appear within 90 seconds. Run the whole helper inside
`nix develop "$REPO_ROOT#theia" --command`.

Check `side02-token-negative`: request `http://127.0.0.1:<port>/sourcerer/health`
with no cookie. Assert the status is 403 AND that the response headers contain no
`Set-Cookie` header of any name — capture headers to a file with `curl -sS -D` and
assert a case-insensitive match count of zero. Both halves must hold; a 403 that
leaks a cookie is a FAIL.

Check `side02-token-positive` (the paired positive control): the same request with
`Cookie: SOURCERER_TOKEN=<token>`. Assert status 200 and that the JSON body parses
and contains an `ok` field that is true and a numeric `pid`.

Check `side02-index-gated`: request `http://127.0.0.1:<port>/` (the index document,
not the health route) with no cookie, and assert 403 — this is the D-98 clause that
static assets and index.html are gated too, which the stock Theia token does not do.
Pair it in the same check with a with-cookie request asserting a non-403 status.

Check `side01-bind-scope`: assert the announced port is actually listening on
127.0.0.1 and on nothing else. Use `ss -ltnH "sport = :<port>"` and assert every
returned local-address field begins with `127.0.0.1:`; assert zero rows whose local
address begins with `0.0.0.0:` or `[::]:`. Additionally assert the port was
OS-assigned rather than a fixed default by asserting the announced port is not 3000.

Record in the script header comment that these checks are expected to FAIL until
plan 04-02 lands the `@sourcerer/token-gate` extension.
