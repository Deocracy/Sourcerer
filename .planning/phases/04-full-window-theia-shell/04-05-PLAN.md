  <action>
Write `sourcerer/INTERNAL-APIS.md` as a table, one row per distinct Firefox
internal reached by `sourcerer/shell/SourcererAPI.sys.mjs`. Columns: the internal
(the API or service actually touched), the `file:line` in `SourcererAPI.sys.mjs`
where it is reached, the exposed `SourcererAPI` method name, the purpose in one
sentence, and threat notes.

Derive the rows from the file, not from memory: run the boundary guard's own
pattern enumeration over `SourcererAPI.sys.mjs` and turn each reported occurrence
into a row. The catalogue must be complete in the strict sense — no occurrence
without a row.

Threat notes must carry, at minimum:
  - the process-spawn row: the spawned backend runs unprivileged but with the
    user's own file access, and Phase 2's D-29 already records that Theia's AI
    terminal is an arbitrary-execution surface reachable once the page loads;
  - the cookie row: the token gates HTTP and the WebSocket upgrade, but Phase 2's
    D-66 records that the origin validator admits callers presenting no origin at
    all, so the token is the only real barrier;
  - the quit-observer row: the browser being force-killed gives the child no
    signal, leaving an orphan — explicitly Phase 5's SIDE-04, named here so the gap
    is documented rather than discovered.

Add a second section, "Deliberately not touched", whose first entry is Firefox's
session store: Phase 4 introduces no persistence and takes no dependency on it, so
the storage ground stays clean for the future unified store (D-107/D-108). Give
each entry a reason, in the same one-row-one-reason discipline
`sourcerer/endpoint-allowlist.json` already uses.

Then make the catalogue self-enforcing. Add a catalogue mode to
`scripts/check-internals-boundary.sh` that scans `SourcererAPI.sys.mjs` with the
same pattern enumeration the default mode uses, and fails when any occurrence has
no matching row in `sourcerer/INTERNAL-APIS.md`, naming the uncatalogued
`file:line`. Extend the script's `--self-test` to also plant a mutated copy of the
catalogue under `mktemp -d` with one row removed, and assert the catalogue check
rejects it and names the missing row. Never mutate the real catalogue.

Register the new mode in `scripts/verify-phase-04.sh` as a check named
`internals-catalogue`, in the `--quick` set alongside the existing boundary checks.
The summary table's row count goes from 9 to 10.
