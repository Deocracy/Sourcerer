<recorded_decisions>
Discretionary choices locked here so the executor implements one concrete thing:

- **Chrome package rides `browser.jar`, not a new jar file.** `jar.mn` opens with
  the existing `browser.jar:` target and declares a *new top-level package* named
  `sourcerer` inside it. This is the exact shape `sourcerer/branding/release/content/jar.mn`
  already uses in this repo, and it avoids a third patch hunk against
  `browser/installer/package-manifest.in` that a genuinely new jar file would
  need — keeping D-93's "020 carries two hunks" literally true.
- **The package is not exposed to web content.** The registration line omits the
  content-accessible flag: nothing on the web should be able to reach
  `chrome://sourcerer/`.
- **`.sys.mjs` modules ship inside the chrome package**, imported as
  `chrome://sourcerer/content/SourcererAPI.sys.mjs`. Precedent in the pinned tree:
  `chrome://global/content/ml/EngineProcess.sys.mjs` is imported exactly this way.
  This keeps D-96's rule stated in one URI scheme.
- **The chrome bootstrap is a classic script, not a module script**, matching the
  Picture-in-Picture player window; ES modules are reached from it via
  `ChromeUtils.importESModule`.
- **stdout is the sentinel channel.** `sourcerer.js` writes sentinels with the
  chrome global `dump()`, enabled by a `browser.dom.window.dump.enabled` default
  in the sidecar pref file. `dump` is a plain global, not one of D-96's forbidden
  internals, so the bootstrap may call it directly.
- **Sidecar pref defaults:** `nodePath` defaults to the empty string, meaning
  "resolve `node` on PATH at spawn time"; `backendMain` defaults to
  `@SOURCERER_DEV_TREE@/theia/applications/browser/lib/backend/main.js`, where the
  define is computed from the mozbuild `TOPSRCDIR` global so no user-specific
  absolute path is ever checked in. Timing defaults:
  `healthIntervalStartupMs` 250, `healthIntervalSteadyMs` 5000,
  `startupTimeoutMs` 90000, `healthTimeoutMs` 4000, `killGraceMs` 3000,
  `logBufferLines` 500.
</recorded_decisions>

  <action>
Create `sourcerer/shell/SourcererAPI.sys.mjs`, exporting a single frozen object
`SourcererAPI`. This is the one file in `sourcerer/` permitted to reach Firefox
internals; every method is a thin named wrapper with no policy of its own, so the
audit surface at the next ESR rebase is exactly this file.

Methods to expose, each wrapping one internal:

  - `getStringPref(name, fallback)` and `getIntPref(name, fallback)` — pref reads
    that return the fallback when the pref is unset, never throw.
  - `getEnv(name)` — environment read.
  - `ensureDirectory(path)` — create the directory and its parents if absent.
  - `pathSearch(command)` — resolve an executable name against PATH, returning
    null rather than throwing when it is not found.
  - `setSessionCookie({ host, path, name, value })` — add a session cookie via the
    cookie manager. The secure flag must be false because the origin is plain
    HTTP on loopback; a secure cookie would never be sent and D-99's whole
    mechanism would silently fail. Use httpOnly true, session true, expiry 0,
    default origin attributes, strict same-site, the HTTP scheme constant, and
    not partitioned.
  - `spawnProcess({ command, args, environment })` — spawn via the subprocess
    module with stderr piped, returning the process handle. Never route a spawn
    through a shell interpreter; the caller supplies an executable path and an
    explicit argument vector.
  - `killProcess(proc, graceMs)` — a single call to the process handle's kill
    method passing the grace period. Do not hand-roll a signal-then-timeout
    sequence: the platform method already sends SIGTERM, waits the grace, then
    SIGKILL.
  - `readPipeChunk(proc, which)` — read the next available chunk of text from the
    named output pipe, resolving null at end of stream.
  - `onQuitGranted(callback)` — register an observer for the topic that fires once
    the quit decision is final and can no longer be cancelled, and return a
    function that unregisters it.
  - `log(level, message)` — mirror one line to the browser console and to stdout,
    so the supervisor's ring buffer and the verification harness read the same
    stream.

Append `content/sourcerer/SourcererAPI.sys.mjs (SourcererAPI.sys.mjs)` to
`sourcerer/shell/jar.mn`, then run the tier-2 rebuild from `upstream/` inside the
firefox dev shell: `MOZCONFIG=../.mozconfig ./mach build faster`. This is not a

Prove the module resolves and behaves by having `sourcerer/shell/sourcerer.js`
