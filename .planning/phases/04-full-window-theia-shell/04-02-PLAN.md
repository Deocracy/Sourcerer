<recorded_decisions>
Choices made here that CONTEXT.md left to Claude's discretion, recorded so the
executor implements one concrete thing rather than choosing again:

- **Port read-back channel:** a stdout sentinel line, not a file.
  `onStart(server)` writes `SOURCERER_BACKEND_READY {"port":N,"pid":N}` followed
  by a newline to `process.stdout`. RESEARCH.md proposed a JSON file under
  `THEIA_CONFIG_DIR`; the sentinel is preferred because the supervisor already
  reads this stdout stream for the D-106 ring buffer, it needs no atomic-write
  or stale-file handling, it dies with the process, and it keeps D-107's
  "Phase 4 writes no state file" literally true. RESEARCH.md's objection to
  stdout was to parsing *Theia core's* prose log line — this sentinel is a
  contract this repo owns, emitted from the same typed `onStart(server)` hook
  RESEARCH.md recommends.
- **Route path:** `/sourcerer/health` (namespaced, so it cannot collide with a
  Theia or plugin route).
- **Token comparison:** constant-time, via Node's `crypto.timingSafeEqual` on
  equal-length buffers, with an explicit length check first.
- **Unconfigured token is fatal.** Without `SOURCERER_TOKEN`, the process logs a
  fatal line and exits with code 78. The alternative — an inert gate — would
  make an ungated backend the result of a *missing* variable, which is the
  failure mode SIDE-02 exists to prevent.
- **Legacy dev bypass is explicitly named.** Phase 1/2's `scripts/smoke-theia.sh`
  and `scripts/verify-phase-02.sh` both start the backend and drive it
  unauthenticated over `http://localhost:3000`. They opt out via
  `SOURCERER_TOKEN_DISABLE=1`, which the chrome side never sets. This keeps the
  only route to an ungated backend a deliberately-typed name rather than an
  omission.
</recorded_decisions>

`src/node/token-gate-backend-contribution.ts`: export an `@injectable()` class
`SourcererTokenGateContribution implementing BackendApplicationContribution`,
with `EarlyExpressMiddleware` injected.

  - `initialize()`: read `SOURCERER_TOKEN` from `process.env` once and store it.
    If it is absent or empty and `SOURCERER_TOKEN_DISABLE` is not set to `1`,
    write a fatal message naming `SOURCERER_TOKEN` to stderr and call
    `process.exit(78)`. If `SOURCERER_TOKEN_DISABLE` is `1`, write a loud
    single-line warning to stderr stating the gate is disabled and return without
    registering anything. Otherwise insert the gate handler at index 0 of
    `this.earlyMiddleware.handlers` using the array's front-insertion method
    (`unshift`). The array-append form the stock contribution uses is forbidden
    here: appending would let the stock cookie-bootstrap middleware run first and
    hand a WebSocket-valid cookie to a caller our own handler is about to reject.

  - the gate handler: read the `SOURCERER_TOKEN` cookie out of `req.headers.cookie`
    by splitting on `;` and `=` and trimming — do not add a cookie-parsing
    dependency. Compare it to the configured token with an explicit length check
    followed by `crypto.timingSafeEqual` over `Buffer.from(...)` of both values.
    On a match, continue the Express chain. On any mismatch, missing cookie, or
    missing header, respond `403` and return without continuing the chain, so no
    downstream handler — including the stock cookie bootstrap — executes for that
    request. Send the 403 with a plain `res.sendStatus(403)`; set no header of any
    kind on the reject path.

  - `configure(app)`: register `GET /sourcerer/health` returning JSON
    `{ ok: true, pid: process.pid, port: <the port captured in onStart, or null> }`.
    Because the gate handler is applied before `configure`'s routes, this endpoint
    inherits the gate with no extra code.

  - `onStart(server)`: read `server.address()`, take `.port` when the address is an
    object, store it for the health response, and write the single line
    `SOURCERER_BACKEND_READY {"port":<port>,"pid":<process.pid>}` plus a newline
    directly to `process.stdout`.

Add `"@sourcerer/token-gate": "0.1.0"` to the `dependencies` block of
