# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — project CLAUDE.md explicitly bans component libraries ("no component library — the design is bespoke"); shadcn gate not applicable |
| Preset | not applicable |
| Component library | none — bespoke CSS Modules against `src/styles/tokens.css` |
| Icon library | none — Unicode glyphs in IBM Plex Mono (`◆ ▥ ¶ ⊹ ≋ ✎ ◎ ◈ ⚷ ⊞ ▦ ✳`), per `src/shell/appletDefs.ts` and the handoff's glyph set |
| Font | IBM Plex Sans / Mono / Serif, locally bundled via `@fontsource/*` (SHELL-04, already shipped Phase 1) — no new font work this phase |

This phase adds **no new design tokens**. Every value below is either already declared in `src/styles/tokens.css` (D-01 of Phase 1's UI-SPEC, extended by Phase 2's Chrome Rework) or a direct extension of the existing `PanelBody`/`LayoutsMenu` patterns. Phase 4 is a **behavioral/contract phase** (registry, host API, stub content) wearing chrome that already exists — the UI work is: (1) a real Applet Catalog picker replacing the '+' cycling hack, (2) a "DEMO" chip added to every stub, (3) per-applet templated stub row content, (4) porting the two rich demos (Wiki, Library) verbatim from the handoff.

## Spacing Scale

Declared values (already in `tokens.css`, unchanged):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, DEMO chip internal padding |
| sm | 8px | Compact element spacing, catalog row horizontal padding |
| md | 16px | Default element spacing |
| lg | 24px | Section padding (stub wrap uses 36px/40px — see exception) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: `PanelBody.module.css` `.wrap` uses `padding: 36px 40px` — a pre-existing off-scale value inherited from Phase 2's shipped placeholder; Phase 4 does not change it (D-11: stub layout is preserved, only new content/chip is added). Catalog picker panel reuses `LayoutsMenu.module.css`'s `.panel`/`.row` metrics (`rail-row-h` = 36px rows) rather than inventing new geometry.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px (`--fs-body`) | 400 (`--fw-regular`) | 1.5 (`--lh-body`) |
| Label / eyebrow / DEMO chip | 11px (`--fs-label`) or 10px (existing `.eyebrow` override) | 400–500 | 1 |
| Heading (stub applet title) | 26px (`--fs-heading`, IBM Plex Serif) | 400 | 1.1 (`--lh-heading`) |
| Display | 12px (`--fs-display`) | 600 (`--fw-semibold`) | 1 |

No new sizes or weights introduced. The DEMO chip (D-12) uses the label role: IBM Plex Mono, 10–11px, uppercase, tracked (`--ls-label-wide: 0.18em`) — matching the existing `.eyebrow` and `DiviChip` mono-chip treatment already in the codebase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0A0B` (`--color-bg`) | Stub/applet body background |
| Secondary (30%) | `#131418` (`--color-panel`) / `#0F1013` (`--color-panel-2`) | Glyph tile background, note box, catalog picker panel |
| Accent (10%) | `#86A38C` (`--color-accent`), hover `#A3BCA8` | Reserved for: glyph-tile icon color, catalog picker active/hover row + focused-row left-border, "focus-or-open" success affordance (opened tab highlight is dockview's own active-tab styling, unchanged), Wiki rich-demo provenance/edit accents (ported verbatim from handoff — do not re-theme) |
| Destructive | `#C42B1C` (`--color-danger`), hover bg `#7a2a24` | Reserved for: Wiki demo's reject/undo action only (if present in the ported handoff interaction) — no other destructive actions exist in Phase 4's scope (no delete-applet, no data-destroying action in stubs) |

Accent reserved for: glyph-tile glyph color (already shipped in `PanelBody.module.css`), Applet Catalog picker row hover/active state (mirrors `LayoutsMenu.module.css` `.row.active`), DEMO chip stays **faint/muted** (`--color-faint`), NOT accent — it must read as a quiet marker, not a call-to-action (D-12 "subtle").

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Applet Catalog picker trigger label: **"+ Open Applet"** (replaces the bare "+" tab-bar button now that it opens a real picker instead of cycling); picker row action is implicit click-to-open, no button label needed per row |
| Empty state heading | Not applicable — Phase 4 has no data-driven empty states (stubs always render their fixed demo content; Home's empty-workspace state is Phase 6 scope) |
| Empty state body | Applet Catalog picker with zero registered keys is unreachable (13 applets are always registered via `appletDefs.ts`) — no empty-state copy needed |
| Error state | `host.ai()` rejection copy is owned by each consuming applet (D-06: "each applet renders its own error UI"); Phase 4 itself defines no user-facing error copy beyond the promise-wrapper's typed error message, e.g. **"Assistant unavailable — try again."** as the default fallback string any stub demo may show if it exercises `host.ai()` in a demo row |
| Destructive confirmation | None in Phase 4 scope — no destructive user actions ship this phase (Wiki's ported apply/undo flow is non-destructive by design: "undo" reverses, it doesn't delete) |
| DEMO marker (D-12) | **"DEMO"** — mono, uppercase, subtle eyebrow/chip, present on every stub applet body (including rich Wiki/Library ports), never on a real applet (Notes, once it lands in Phase 5, carries no DEMO chip) |
| Stub note box (existing, unchanged) | Keep `PanelBody.module.css`'s existing dashed note-box copy pattern for the ~11 templated-stub applets; per-applet demo row content (D-13) is data, not copy-contract — Kanban gets fake card titles, News gets fake feed-item titles, etc., authored believably per applet during planning/execution, not specified token-by-token here |

## Component Inventory (new this phase)

| Component | Contract |
|-----------|----------|
| **Applet Catalog picker** (D-18) | Replaces the '+' key-cycling hack in `Dock.tsx`. Trigger: same tab-bar '+' affordance, opens a `LayoutsMenu`-style dropdown panel (absolute-positioned, `--color-bg` bg, 1px `--color-line` border, radius 0, 36px rows). Each row: glyph (mono, `--color-accent`) + title (sans, `--color-fg`) + one-line desc (sans, `--color-muted`, truncated) sourced from `appletDefs`. Click → `host.open(appletKey)` (focus-or-open per D-17). Keyboard: ArrowUp/Down + Enter, mirroring `LayoutsMenu`'s existing `WR-06` focus pattern. No search/filter in v1 (13 items fits one scroll list at 36px rows = 468px, within the existing `max-height: 320px` scroll pattern). |
| **DEMO chip** (D-12) | Small mono eyebrow/chip, `--color-faint` text, positioned top-left of every stub body (templated and rich). Templated stubs: added to `PanelBody.module.css`'s existing `.eyebrow` row (e.g. "APPLET · WIKI · DEMO" or a separate adjacent chip — implementation detail, Claude's discretion, but visually subtle, never accent-colored, never a full banner). |
| **Templated stub body** (D-10, D-13) | Existing `PanelBody` component, extended per-applet with believable demo rows where cheap (Kanban cards, News items) and generic where not (per D-13, planner/executor discretion) — visual chrome (glyph tile, serif title, dashed note box) is UNCHANGED from the already-shipped Phase 2 styling. |
| **Rich Wiki/Library stub bodies** (D-10) | Ported verbatim from `design-sync-setup-guide/design_handoff_bespoke_rails_shell/wiki.js` and `library.js` — pixel-accurate port, not a redesign. These two already carry the handoff's own token usage (inline `T` color object → map onto existing `tokens.css` custom properties per CLAUDE.md's CSS strategy). DEMO chip is the only NEW visual element added on top of the ported demos. |
