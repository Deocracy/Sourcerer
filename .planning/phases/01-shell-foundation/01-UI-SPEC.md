# Phase 1 — UI Design Contract

> Visual and interaction contract for the frameless window + custom title bar. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** `Design sync setup guide/design_handoff_sourcerer_tauri/README.md` (LOCKED — high-fidelity, "recreate pixel-perfectly"). All tokens/metrics below are extracted from that handoff plus the reference prototype (`reference/Working Sourcerer UX UI Prototype.dc.html` lines 26-78, the `TITLE BAR` block) — none are invented. No CONTEXT.md/RESEARCH.md exist yet for this phase; nothing in this contract required a user question because the handoff answers every design decision in scope.

Exceptions (fixed chrome metrics — locked by the handoff, not on the 4pt scale):

| Metric | Value | Element |

| Icon button zone | 34px × 24px | Rail-cycle / assistant-toggle buttons (present in full design; NOT wired in Phase 1 — see "Phase Boundary Note" below) |

| Maximize glyph | 10px × 10px, 1px border | Square outline icon inside its 46px zone |
| Border width | 1px, always | Title bar bottom border, app window outer border — never 2px+, never blurred |
| Border radius | 0, everywhere | Except the logo circle noted above |

## Typography

The full three-family type system (Sans / Mono / Serif) must be bundled and load-verified in Phase 1 (SHELL-04), even though the Phase 1 title bar visually uses only Mono. Later phases (tabs, rail, applet stubs, assistant) depend on Sans/Serif being correctly bundled now.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (title bar wordmark "Sourcerer") | 12px, IBM Plex Mono | 400 | 1 (single line); letter-spacing 0.08em |
| Label (title bar crumb, e.g. "Home") | 11px, IBM Plex Mono | 400 | 1 (single line); color dim `#6E6C66` |
| Body (project-wide type scale; not rendered by Phase 1 chrome, established for Phase 2+) | 13px, IBM Plex Sans | 400 | 1.5 |
| Heading (project-wide type scale; stub/applet titles, not rendered by Phase 1 chrome) | 26px, IBM Plex Serif | 400 | 1.1 |

Weight budget available project-wide (bundle now per SHELL-04, use progressively): Sans 400/500/600 · Mono 400/500 · Serif 400 + 400-italic. **Phase 1 chrome itself uses only Mono weight 400** — do not introduce 500/600 into the title bar; those weights exist so Phase 2+ doesn't need a second font-loading pass.

Micro-label convention (applies to crumb, and to Mono labels added by later phases): uppercase where the source says so, letter-spacing 0.08–0.18em.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0A0B` (bg) | Title bar background, app window background |
| Secondary (30%) | `#131418` (panel) | Hover background for icon-zone buttons (rail/assistant toggle, layouts menu) — visually present in the full bar, not functionally wired until their owning phase |
| Accent (10%) | `#E6E4DE` (fg) | Reserved for: logo ring stroke + logo dot fill, "Sourcerer" wordmark text, close-button glyph color on hover (against the danger-hover background) |
| Destructive | `#7a2a24` (danger-hover) | Close button hover background ONLY — no other element in Phase 1 uses this color |
| Border / line | `#1E1F22` (line) | Title bar bottom border, app window outer border — always 1px |
| Muted / dim | `#6E6C66` | Default (non-hover) color for minimize glyph, maximize glyph border, active-applet crumb text |
| Muted-hover | `#A5A29A` (fg-mid) | Minimize button glyph color on hover |

Accent reserved for: logo mark (ring + dot) and wordmark text only, plus the close button's hover-state glyph. Never use `#E6E4DE` as a generic "interactive element" color in Phase 1 — it is a specific-elements list, not a default.

**Primary focal point:** the logo/wordmark cluster (top-left, accent `#E6E4DE`, clickable `openHome` handler) draws the eye first and stays stable across all applet states. Everything else in the bar is dim (`#6E6C66`) by default and only lifts to `#A5A29A`/accent on hover — the accent-vs-dim contrast is what establishes the hierarchy, not size or weight.

## Platform Notes (DPI + Fonts) — supports SHELL-03 / SHELL-04

- **DPI (SHELL-03):** All chrome metrics in this contract are CSS logical pixels (e.g. `34px`, `1px`). Do not hand-roll `devicePixelRatio` scaling in the title bar — Tauri/Windows handles logical→physical pixel mapping via Per-Monitor-V2 DPI awareness. Verify `tauri.conf.json` does not force `dpiAware: false` and that no CSS uses hard-coded physical-pixel hacks (e.g. `0.5px` border tricks). Test the 1px border and 34px bar height render crisply (not blurry, not off-by-one) at Windows display scaling 100%, 125%, and 150% before marking SHELL-03 done — this was flagged as an explicit open verification item in `.planning/STATE.md` ("Confirm PerMonitorV2 DPI awareness so 1px borders hold at 125%/150% scaling").
- **Fonts (SHELL-04):** Import per-weight `@fontsource` CSS subpaths only for weights actually in the budget above (`@fontsource/ibm-plex-mono/400.css` etc.) — never the "all weights" index import. Confirm via devtools Network tab that zero requests go to `fonts.googleapis.com` or `fonts.gstatic.com` at runtime (the prototype's `<helmet>` block references those — it is reference-only, do not port those `<link>` tags).

## Phase Boundary Note

The full 34px title bar in the handoff also includes a "◱ LAYOUTS" menu button and two 34×24px icon buttons (cycle rail, toggle assistant) between the crumb and the window controls. These belong to **PERS-02** (Phase 3), **RAIL-01** (Phase 2), and **ASST-\*** (Phase 6) respectively — none are in SHELL-01..04. Per this project's "stay in phase boundary" convention: **do not render these three elements in Phase 1.** Build only: logo + wordmark + "·" + crumb (left cluster) → flex spacer (drag region) → window controls (right cluster). The spacer's flex-basis simply absorbs the space those elements will occupy later; no placeholder chrome needed now.

## Interaction Contract (SHELL-02)

- Drag region = the empty flex spacer between the left cluster and the window controls ONLY (`data-tauri-drag-region` in Tauri terms). Confirmed by handoff: "Title bar drag region = the empty flex spacer only." No button, icon, or the logo/wordmark cluster may carry the drag-region attribute — clicking the logo must fire its own `openHome` handler, not initiate a window drag.
- Window controls wire directly to the Tauri window API: minimize → `appWindow.minimize()`, maximize/restore → `appWindow.toggleMaximize()` (must reflect actual maximized state on the icon/aria-label), close → `appWindow.close()`.
- Hover states are flat color shifts only, no transitions, no shadows (per handoff "Interactions & Behavior" — global convention, applies here): minimize hover → bg `#131418`, glyph `#A5A29A`; maximize hover → bg `#131418` only; close hover → bg `#7a2a24`, glyph `#E6E4DE`.
- Logo/wordmark cluster click → `openHome` handler (toggle Home ⇄ last applet view). In Phase 1, since no workspace exists yet, this can be a no-op or console-stub — do not block on Phase 2/6 to satisfy SHELL-01/02.
