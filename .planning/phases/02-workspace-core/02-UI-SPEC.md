## Chrome Rework (Phase 1 → Phase 2 delta)

Phase 1 shipped a 34px frameless title bar with white `#E6E4DE` accent and 0 border-radius
everywhere. Phase 2 reworks this to the new handoff. These token changes are **prerequisites** for
RAIL/DOCK work to render inside the correct shell frame — call them out explicitly in the plan so
the executor doesn't build rail/dock chrome against stale Phase 1 tokens.

| Token | Phase 1 (shipped) | Phase 2 (this spec) |
|-------|--------------------|-----------------------|
| `--titlebar-h` | 34px | **40px** |
| Window frame | frameless, edge-to-edge, 0 radius | **floating rounded window**: 20px inset padding on the fixed backdrop, 10px border-radius on the inner card, 1px `#1E1F22` border, shadow `0 24px 70px -10px rgba(0,0,0,0.75), 0 4px 14px rgba(0,0,0,0.5)`. Requires Tauri `transparent:true` + a radial-gradient backdrop `radial-gradient(120% 120% at 50% -10%, #0E0F12 0%, #050506 60%, #030304 100%)` filling the OS-level window, with the actual app chrome as the inset rounded card. |
| `--color-fg` (accent role) | `#e6e4de` (white) used as accent | **`#86A38C` (green)** is now the accent color; `#E6E4DE` demotes to primary text color only |
| `--radius` | 0 everywhere | 0 everywhere **inside** the card (rail rows, tabs, buttons, inputs) — the 10px radius applies ONLY to the outer window card, nowhere else |
| Title bar content | logo circle + "Sourcerer" wordmark + "·" + active-applet crumb | "Sourcerer" wordmark (Plex Sans 12px/600) + **DIVI toggle chip** (Plex Mono 11px, pill-less rectangular chip: active = accent border + `rgba(134,163,140,0.14)` bg + accent text; inactive = `#26272B` border + muted text) + `— {corpus name}` in faint mono + two rail-toggle SVG buttons (16×12, fill to show rail state) + window controls (Minimize 11×1px bar, Maximize 9×9px square outline, Close ✕ hover bg `#C42B1C`) |

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 1's locked scale, still governs all
non-chrome spacing (row padding, gaps, section breaks):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline spacing |
| sm | 8px | Compact element spacing, rail resize-handle hit zones |
| md | 16px | Default element spacing, rail row horizontal padding baseline |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions (fixed chrome metrics, NOT on the 4pt scale — locked by the handoff, do not round to
nearest 4px):
- `--titlebar-h: 40px` ✓ (already a multiple of 4)
- `--tab-bar-h: 34px` — **not** a multiple of 4; this is a dockview-owned CSS var (`--dv-tabs-and-actions-container-height`) fixed by the handoff, exempt from the 4pt rule.
- `--rail-row-h: 36px` — not a multiple of 4; fixed rail row height per handoff, exempt.
- `--rail-resize-handle-w: 6px`, drop-zone edge trigger `28%` of pane width — fixed interaction geometry, exempt.
- `--winctl-w: 46px` (carried from Phase 1, unchanged) — exempt.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (UI/labels/rail item labels) | 13px (Plex Sans) | 400 | 1.5 |
| Label (mono badges, uppercase section headers, tab text) | 11-12px (Plex Mono) | 400 | 1 |
| DIVI toggle chip (title bar) | 11px (Plex Mono) | 500 | 1 |
| Rail glyph column | 18px (Plex Mono) | 400 | 1 |
| Heading (applet titles — not exercised by rail/dock chrome, reference only) | 26px (Plex Serif) | 400 | 1.1 |
| Wordmark ("Sourcerer") | 12px (Plex Sans) | 600 | 1 |

**Weight exemption — 3rd weight locked by design handoff, not a discretionary choice.** This spec
declares 3 font weights (400, 500, 600), exceeding the generic 2-weight guideline. Verified directly
against `design-sync-setup-guide/design_handoff_bespoke_rails_shell/Sourcerer Bespoke Rails.dc.html`:
line 67 sets the wordmark to `font-weight: 600`; line 68 sets the DIVI toggle chip to
`font-weight: 500` explicitly (Plex Mono, 11px); line 111 sets the rail badge-count digit to
`font-weight: 600` (Plex Sans, 9px). Weight 400 is the implicit default for every other label/body
element (no explicit override in the handoff markup). All three weights are genuinely exercised by
Phase-2 title-bar chrome built this phase (wordmark, DIVI chip, badge digits) — this mirrors
CLAUDE.md's supporting-libraries table, which explicitly locks bundling weights 400/500/600 sans (plus
400/500 mono) for pixel-fidelity reasons, not as a discretionary typography preference. Consolidating
the DIVI chip to 400 or 600 would deviate from the adopted source of truth; it is not done here.

Letter-spacing: mono uppercase labels (DIVI chip, section headers) use 0.04–0.18em tracking per
element — reuse the existing `--ls-wordmark: 0.08em` token pattern, add `--ls-label-wide: 0.18em`
for the widest tracked labels (session-name input, uppercase section headers).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0A0B` | App/window background, dockview `--dv-background-color`, active tab bg |
| Secondary (30%) | `#131418` | Rail panel bg (hover), tab-bar/panel-2 recessed surfaces (`#0F1013` for tab containers/inputs) |
| Accent (10%) | `#86A38C` (hover `#A3BCA8`) | Reserved for: active rail item left border (2px), DIVI chip active state (border + text + 14% bg tint), dockview drag-over highlight (`--dv-drag-over-border-color`/`background-color` at 14% opacity), drop-zone overlay border during rail-drag-to-dock (18% fill), model-picker accent dot (Phase 6, not this phase) |
| Destructive | `#C42B1C` | Close-button hover only (title bar); no other destructive actions exist in this phase's scope (rail/dock has no delete-with-confirmation flow — closing a tab is reversible via reopen, not destructive) |

Accent reserved for (explicit — nothing else may use `#86A38C`): active rail-item left border,
DIVI toggle chip active state, dockview drag-over/drop-target highlighting, rail drag-out drop
overlay (accent border + 18% accent fill). Everything else interactive (default rail hover, tab
hover, resize-handle hover) uses neutral `rgba(230,228,222,0.28)` or `#3A3B40`/`#26272B` — accent
is NOT a general-purpose "interactive" color in this system.

## Copywriting Contract

Phase 2 is chrome/interaction (rail + dock), not a data-entry surface — most copy is structural
labels, not prose. Documented for completeness per checker requirement:

| Element | Copy |
|---------|------|
| Primary CTA | "+" icon button in each dockview tab bar to open a new applet panel (no text label — glyph-only, title attr "Open applet") |
| Rail catalog entry | "Applet Catalog" (footer row label, opens the full applet list — Phase 4 scope for actual catalog content, but the row itself renders this phase) |
| Empty workspace fallback | Not a bare empty state. Per handoff: if no saved dockview layout exists (or it's corrupt), the workspace auto-opens **Wiki** then **Library** as default panels — no "no panels open" empty-state copy is needed in this phase. (A true empty metro-card Home dashboard is Phase 6/HOME-01 scope, gated behind the DIVI toggle, not built here.) |
| Corrupt layout fallback | Silent recovery, no user-facing error copy — a canary localStorage key detects a crash-on-restore and drops the saved layout before it can re-crash; user just sees the default Wiki+Library panels reappear. No toast/banner required this phase. |
| Loading state (dockview mount) | "LOADING…" — centered, mono, faint color, uppercase tracking (matches `LOADING DASHBOARD…` pattern in the handoff for consistency) |
| Failure state (dockview import fails) | "DOCKVIEW FAILED TO LOAD" — centered, mono, same treatment as loading state |
| Destructive confirmation | None in this phase's scope. Closing a tab/panel is a reversible UI action (re-open via rail or "+"), not a destructive-with-confirmation flow. No modal/toast copy needed. |

## Component/Interaction Inventory (Phase 2 specific — supplements the generic template)

### Left Rail (RAIL-01, RAIL-02, RAIL-03)

- **Modes**: `expanded` (default 220px, resizable to 520px max) / `compact` (56px, 40×40 icon
  tiles) / `hidden` (6px hover-to-reopen strip). Cycled by: clicking the rail's own toggle, ⌘\ /
  Ctrl+\, or double-clicking the 6px resize handle on the rail's right edge.
- **Drag-to-resize**: live width `raw`; below `CLOSE_AT` (44px) snaps to hidden (6px); below
  `COMPACT_AT` (132px) snaps to compact (56px); else expanded at the dragged width, clamped to
  `[132, 520]` when expanded.
- **Row anatomy (expanded)**: 36px height, 26px glyph column (Plex Mono 18px) + label (Plex Sans
  13px, ellipsis-truncate) + optional badge (12px pill, muted `#A5A29A` bg, dark text, top-right in
  compact / inline-right in expanded). Active row: 2px accent left border + `#131418`/`#1E1F22` bg.
  Hover (non-active): bg `#131418`.
- **Row anatomy (compact)**: 40×40 centered glyph tile, badge as 12px pill top-right overlay.
- **Applet order** (fixed array, not user-configurable at the array level — only reorderable within
  it): `Sources, Library, Wiki, Graph, Chat, Writing, Browser, Kanban, News, KeyPass, Builder,
  Dadabase, Notes`. Footer group (pinned, always last): "Applet Catalog" row, then user block
  (avatar "C" serif italic initial + "Casey / HUMAN" + settings gear ⚙).
- **Drag interactions**: 5px movement threshold before a drag registers (below threshold = treated
  as a click → open/focus that applet). Within-rail drag = reorder via a drop-line indicator
  between rows (splice-based, `arrayMove` semantics on `railOrder`). Drag *out* past the rail's
  right edge into the workspace = dock as a new panel — green drop overlay (`rgba(134,163,140,0.18)`
  fill + accent border), with split zones at the outer **28%** of the target dockview group's
  bounding rect mapping to left/right/top/bottom (`referenceGroup` + `direction` passed to
  dockview's `api.addPanel`), center 44% = tab-join. A floating ghost (glyph + title, `#131418` bg,
  `#26272B` border) follows the cursor during the drag.
- **Badge counts**: sourced from shell store (e.g. Wiki review count) — render as the 12px pill
  described above; this phase renders the badge UI and wiring to a store value, not the actual
  count-producing logic (that's Phase 4/5 applet scope — badge should read whatever the store slice
  currently holds, defaulting to 0/hidden-if-zero).

### Center Dock (DOCK-01 through DOCK-06)

- **Engine**: dockview-core, single instance, fills the center grid column
  (`position:absolute; inset:0`). Theme via the `.sourcerer-dock` class mapping every `--dv-*`
  variable listed in "Dock Theme Tokens" below — do not hand-roll tab/split chrome, theme the
  library.
- **Tabs**: 34px bar height, 12px mono tab font, tabs container hides its own scrollbar
  (`scrollbar-width: none`). "+" button opens a new applet in the active group.
- **Drag/dock**: dockview's native drag-to-reorder-within-bar and drag-between-bars/zones apply
  as-is (this is the library's own behavior, not bespoke — theme only, don't reimplement).
  5-zone docking (center/left/right/top/bottom of a target group) plus edge-splits at the whole
  workspace boundary are dockview defaults, styled via `--dv-drag-over-background-color`
  (`rgba(134,163,140,0.14)`) and `--dv-drag-over-border-color` (`#86A38C`).
- **Splits/resize**: dockview's own separator/resizer chrome, styled via
  `--dv-separator-border: #1E1F22`. Do not hardcode a bespoke "5px resizer" — that figure is a
  holdover from the pre-dockview generic requirement text; defer to dockview's actual resizer
  hit-area/visual (verify exact px against the installed `dockview-core@2.0.0` package once added,
  don't invent a value not present in the handoff).
- **Multi-instance panels (DOCK-04)**: panel `id` is `key + ':' + Date.now()` in the prototype —
  port as `key:{nanoid}` or similar stable-per-instance id scheme (project already locks nanoid for
  instance ids) so multiple Wiki/Notes/etc. panels can coexist with distinct `instanceId`s passed to
  `host`.
- **Focus (DOCK-05)**: dockview's `onDidActivePanelChange` is the source of truth for "focused
  pane" — route keyboard input to whatever panel dockview reports active; no bespoke focus-tracking
  needed, consume the library's own event.
- **Empty/fallback (DOCK-03)**: NOT a bare "empty tree renders Home" — on load, if no saved layout
  restores (missing, corrupt, or zero panels after restore), clear and auto-open `Wiki` then
  `Library` as the default two panels. Layout persists to
  `localStorage['sourcerer-dockview-bespoke-v2']` (rename the key to match this project's naming if
  a different persistence key convention is established in Phase 3 — Phase 2 can use this literal
  key as a placeholder since PERS-01..04 formally owns persistence strategy) with a 300ms debounce
  on `onDidLayoutChange`, guarded by a canary key that detects and discards a layout that crashes
  the restore.
- **Panel body dispatch**: `makeRenderer` maps applet key → mount function (`Wiki`→`mountWiki`,
  `Library`→`mountLibrary`, `Settings`→`mountSettings`, `Home`→`mountHome`, anything else → generic
  placeholder body: glyph + title + description + dashed note box). Phase 2 only needs the
  dispatcher and the generic placeholder body — real applet bodies (Wiki/Library/etc.) are Phase 4
  demo-stub / Phase 5 Notes scope, not this phase's job. Build the placeholder body to spec now so
  Phase 4 has a proven mounting seam.
- **Clamp bounds (DOCK-06)**: rail `[6, 520]` px per the mode-snap thresholds above; dockview's
  internal pane min-size is a library default (verify against `dockview-core@2.0.0` docs once
  installed — the handoff does not override it, so don't invent a number). Right-assistant clamps
  (`[180-close, 620-full]`) are documented here for completeness but are Phase 6 build scope.
