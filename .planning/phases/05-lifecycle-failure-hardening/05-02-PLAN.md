<recorded_decisions>
Discretionary constants, locked (CONTEXT.md "Claude's Discretion"), all shipped
as prefs in `sourcerer-sidecar.js` rather than literals so a verification run can
force a fast give-up from a profile `user.js`:

- `sourcerer.sidecar.giveUpAttempts` = **6**. With the existing backoff (500 ms
  doubling to a 5000 ms cap) six attempts spend about 17.5 seconds waiting, plus
  spawn and health-gate time — long enough to ride out a slow machine, short
  enough that a real failure surfaces inside a minute.
- `sourcerer.sidecar.giveUpWallclockMs` = **45000**. Whichever ceiling trips
  first ends the retry. The wall-clock ceiling exists because a slow-failing
  spawn would otherwise get far fewer real attempts than a fast-failing one.
- `sourcerer.sidecar.recoveryProbeIntervalMs` = **15000**, three times the
  steady-state health interval. Deliberately slow: it exists to notice a backend
  that healed on its own, not to be a second health loop.

Other locked choices:

- **Classification carrier:** `_spawnAndGate` returns `{ ok, recoverable, reason }`
  instead of a bare boolean at every existing return site. `reason` is a short
  human-readable string reused verbatim as the error layer's message, so the
  message is written once.
- **Unrecoverable set (D-113):** the backend entry file pref unset or missing;
  the Node executable unresolvable; the spawn call itself throwing; and D-112's
  case, the pinned port being held by something else on a respawn. Everything
  else is recoverable.
- **Error-layer shape (D-116):** message line, a Retry button, and a control that
  opens the diagnostics layer. No log tail, no stack trace — detail belongs to
  SHELL-04 and is implemented once.
- **Deck stacking (D-114/D-94):** the error layer is a fixed, full-inset sibling
  of the existing loading layer at a higher stacking index, in the same dark
  background and light text family and the same sans-serif face. Nothing about
  the content browser element changes when it shows.
- **Chrome automation:** Task 1 decides it with a discriminator, not an
  assumption. The visible-state assertions in this plan are written against
  stdout sentinels, which work regardless of the outcome; only the Retry-button
  click depends on the driver.
</recorded_decisions>
