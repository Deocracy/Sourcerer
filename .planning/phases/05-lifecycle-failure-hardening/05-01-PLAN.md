and make a leftover from a previous crash detectable and reapable on the next
startup.

developer a manual `pkill`.

<recorded_decisions>
Discretionary choices locked here so the executor implements one concrete thing
(CONTEXT.md `<decisions>` "Claude's Discretion"):

- **Watchdog package (D-109 discretion):** the watchdog lives in the existing
  `@sourcerer/token-gate` package as its **own file and its own contribution
  class**, bound alongside the token gate in the existing backend module. Reason:
  a new sibling workspace package costs a `package.json`, a `tsconfig.json`, a
  `theia/package.json` build-script entry, an app dependency entry and a fresh
  `yarn install` — six touches of build wiring for roughly fifteen lines of
  runtime code. A separate *class* (not a separate package) is what actually
  matters: the token gate returns early from its own `initialize()` on the named
  dev bypass and calls `process.exit(78)` on a missing token, so folding the
  watchdog into that method would silently disarm it on both paths.
  `ponytail: same package, separate class; split it out if a second lifecycle
  concern ever joins it.`
- **Arming condition:** the watchdog arms only when the environment variable
  `SOURCERER_SUPERVISED` reads exactly `1`. Without this gate a backend started
  by `yarn start`, `scripts/smoke-theia.sh` or `verify-phase-04.sh`'s own
  `start_backend` would see an immediately-closed or redirected stdin, take it
  for parent death, and terminate itself — breaking three existing green checks.
- **Self-termination path (D-109):** the watchdog re-signals its own process with
  `SIGTERM` rather than calling `process.exit()`, because Theia's
  `BackendApplication` already installs a `SIGTERM` handler that runs
  `gracefulShutdown()` and its `@preDestroy` hooks.
- **State file (D-110 discretion):** `sidecar-state.json`, written into the
  already-resolved `_configDir`, holding `pid` (number), `port` (number),
  `startTicks` (string, the raw field-22 value, unconverted), and `writtenAt`
  (`Date.now()`, for diagnostics only — never used in the identity decision).
  Written atomically through `IOUtils`' own temp-path-then-rename option, never a
  hand-rolled two-step.
- **Identity check (D-111 discretion):** `/proc/<pid>/stat` start-time ticks,
  string equality, and nothing else. Not a health-path probe: D-125's positive
  control plants a synthetic sleeping process that can never answer a health
  route, so a health-probe identity check would refuse to reap the very fixture
  that proves reaping works.
- **Signal used for a verified leftover:** `SIGTERM` (15). Liveness is tested by
  signalling 0 through the same call. A leftover that ignores `SIGTERM` is logged
  and left alone rather than escalated — escalation on a process this browser did
  not spawn is exactly the over-broad action the prohibitions forbid.
</recorded_decisions>

Add five methods to the frozen `SourcererAPI` object, each a thin named wrapper
following the file's existing conventions.

`writeStateFile(path, value)` writes JSON through `IOUtils`, passing the
temp-path option so the platform performs write-then-rename; the temp path is the
destination path with a `.tmp` suffix. `readStateFile(path)` reads JSON and
resolves `null` on any failure — absent file, malformed content, wrong type —
following the never-throw read convention. `removeStateFile(path)` removes the
file, relying on the platform's own absent-file tolerance rather than a prior
existence check.

`readProcessStartTicks(pid)` reads `/proc/<pid>/stat` as UTF-8 and returns field
22 as a string, or `null` on any failure. Locate the **last** closing parenthesis
in the line and slice from two characters past it before splitting on spaces —
the second field is the executable basename, is parenthesised, and may itself
contain spaces and parentheses, so splitting the whole line misaligns every later
field. After that slice, field 22 is index 19.

`signalBarePid(pid, signal)` opens `libc.so.6` through js-ctypes, declares the
libc `kill` function with the default ABI and three integer arguments, calls it,
and closes the library in a `finally` block. It returns true only when the call
returned 0. Add a `ctypes` entry to the module-level lazy-getter block for
`resource://gre/modules/ctypes.sys.mjs`. This project is Linux-only, so no
cross-platform branch is wanted.

In `TheiaService`, add a `_stateFilePath` field and derive it in `start()`
immediately after `_configDir` is resolved, as `sidecar-state.json` inside that
directory.

In `_spawnAndGate`, after the ready sentinel has been parsed and `this._port` and
`this._pid` are set, read the new backend's start ticks and write the state file
with the pid, the port, those ticks and the current timestamp. Do this on every
successful spawn, first and respawn alike, so a crash after a restart still leaves
an accurate record. Push one line into the ring buffer naming what was written.

In `stop()`, after the backend has been signalled and the process handle cleared,

find.

Add `_reapLeftover()` and call it from `start()` after the config directory is
created and **before** the first `_spawnAndGate` call. It reads the state file;
`null` means nothing to do and it returns silently. With a record in hand it
signals the recorded pid with signal 0 to test liveness — a failed signal means
the process is gone, so it removes the stale file and returns. If the pid is
alive it reads that pid's current start ticks and compares them for exact string
equality against the recorded value. On a mismatch it logs a line naming the
recorded and observed values, removes the file, and **returns without
signalling** — the operating system has recycled that pid onto an unrelated
process, and signalling it would reach something the developer owns. Only on an
exact match does it send signal 15, poll briefly for the pid to disappear, log the
outcome, and remove the file. A leftover that survives the signal is logged and
left alone; there is no escalation and no second signal.

Route every log line through the existing `_pushLog`/`_fatal` pair — no third
logging path.
