# Phase 5 — UI Design Contract

> Visual and interaction contract for the Notes applet. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — CLAUDE.md explicitly bans component libraries ("no component library — the design is bespoke... Component libraries impose their own spacing/radius/shadow defaults that fight this"). No `components.json` present; shadcn init gate intentionally skipped per project mandate, not asked of the user. |
| Preset | not applicable |
| Component library | none — bespoke CSS Modules keyed to `src/styles/tokens.css` |
| Icon library | none — the shell uses single-glyph Unicode characters (e.g. Notes' rail glyph `✳`) as the entire "icon" system, never an SVG icon set |
| Font | IBM Plex Sans (body/UI), IBM Plex Mono (labels/eyebrows/DEMO-chip-style crumbs), IBM Plex Serif (headings) — all locally bundled via `@fontsource/*`, no runtime Google Fonts |

Notes is Phase 5's applet body rendered inside the existing dockview panel chrome (34px tab bar, panel host) shipped in Phases 2/4 — this spec covers only the Notes applet's own content area, not shell chrome (title bar, rail, dock), which is already built and out of scope.

Exceptions: `--rail-row-h` (36px) is reused verbatim for the Notes list-row height, matching `LayoutsMenu.tsx`'s row pattern — not a new metric, an existing fixed chrome constant.

## Typography

Sourced verbatim from `src/styles/tokens.css` — Notes introduces zero new sizes/weights (project already declares exactly 4 sizes / 3 weights and Phase 5 must not add a 5th):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (note list row text, editor body textarea) | 13px (`--fs-body`) | 400 (`--fw-regular`) | 1.5 (`--lh-body`) |

Sourced verbatim from `src/styles/tokens.css` — Notes introduces zero new colors:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` `#0a0a0b` | Panel background, editor background |
| Secondary (30%) | `--color-panel` `#131418` / `--color-panel-2` `#0F1013` | List-row hover background (`--color-panel`), title/body input recessed background (`--color-panel-2`, matching `LayoutsMenu.module.css` `.nameInput`) |
| Accent (10%) | `--color-accent` `#86A38C` (hover `--color-accent-hover` `#A3BCA8`) | Reserved for exactly: the selected/active note row's left border + title color (mirrors `LayoutsMenu.module.css` `.row.active`), the "New Note" primary button, the AI-summarize action button/label, focus state of the title/body inputs |
| Destructive | `--color-danger` `#C42B1C` (hover `--color-danger-hover` `#7a2a24`) | Delete-note action only — icon/button hover color, never resting state (mirrors `LayoutsMenu.module.css` `.delete:hover`) |

Accent reserved for: selected-note row indicator + label, "New Note" button, "Summarize" AI action button — nowhere else. Body text stays `--color-fg` (#e6e4de) / `--color-fg-secondary` (#C5C2BA); muted UI (timestamps, empty-state copy, eyebrow) stays `--color-faint` (#6E6C66) / `--color-muted` (#A5A29A), exactly matching the DEMO-chip and eyebrow treatment already established in `TemplatedStub.module.css` and `Library.module.css`.

## Layout

Two-pane split within the applet's panel body, matching the shell's existing split-pane visual language (1px `--color-line` divider, 0 border-radius everywhere per `--radius: 0`):

- **List pane** (left, fixed ~240px width): scrollable list of notes, each row `--rail-row-h` (36px) tall, title + relative timestamp (secondary line), selected row gets `2px solid var(--color-accent)` left border (mirrors `--rail-active-border` token literally) and accent-colored title. "+ New Note" affordance pinned at the top of the list pane (mono label button, matches `LayoutsMenu.module.css` `.footerRow` treatment inverted to a header slot).
- **Editor pane** (right, flex-fill): title input rendered at `--fs-heading`/`--font-serif` (borderless, `--color-panel-2` background only on focus per the input pattern already used for `LayoutsMenu`'s `.nameInput`), body textarea at `--fs-body`/`--font-sans`, both auto-saving to `host.storage` on blur/debounced change (no explicit Save button — matches the "quick capture" framing from `appletDefs.ts`'s Notes description). A toolbar row above the body holds: relative-timestamp label (muted, mono), delete-note icon button (danger-on-hover only), and the "Summarize" AI action button (accent).
- When no note is selected (or the note list is empty), the editor pane renders the empty state (see Copywriting) instead of blank inputs.
- Every applet still carries the D-12 subtle "DEMO" chip convention for *stub* applets only — Notes is real (FWK-02 stub replacement), so **no DEMO chip renders** once this ships; the eyebrow reads `APPLET · NOTES · NOTE` without the chip, matching the non-stub eyebrow pattern already established for Wiki/Library's rich (non-templated) demos minus their DEMO marker.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "+ New Note" (creates and selects a blank note, cursor lands in the title input) |
| Empty state heading | "No notes yet" |
| Empty state body | "Create your first note to start capturing quick thoughts. Notes save automatically and can graduate into the corpus later." + "+ New Note" action repeated inline |
| Error state (AI summarize failure) | "Couldn't summarize this note." + "Check your connection and try again." (mirrors Phase 7's honest-degrade discipline — one error, never a hang; matches D-06's "each applet renders its own error UI" contract) |
| Error state (storage read/write failure) | Silent best-effort fallback per FWK-04 D-16 (never surfaces a raw error to the user for storage — matches `workspaceStore.ts`'s never-throw discipline); if a write demonstrably fails, show inline "Not saved — retrying" next to the toolbar timestamp, not a blocking modal |
| Destructive confirmation | Delete note: clicking the delete icon shows an inline two-step confirm (button label flips to "Delete for real?" for 3s, matching `LayoutsMenu.module.css`'s `.delete` hover-reveal pattern rather than a modal dialog — no modals anywhere in this shell) |
| AI action label | "Summarize" (button); while in-flight, label becomes "Summarizing…" (disabled); result renders inline below the toolbar as a muted, serif-italic block (mirrors the assistant's proposal-quote-block visual language reserved in Phase 6, applied here at small scale since Notes is `host.ai()`'s first real consumer) |
