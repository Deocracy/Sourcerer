*Layer 1 — static prefs.* For each entry in the allowlist's `prefs` array, read
the effective default value from the installed pref surfaces under
`objdir/dist/bin` (`greprefs.js` and the installed branding/browser default pref

not a skip. Its positive control restores one known-blanked URL pref to a

it must restore the original file afterwards even on failure.

*Layer 2 — filesystem, exact-path strace (BRAND-03).* Run the binary under
`strace -f -e trace=openat,open,stat,access` writing to a log, in a short
`--headless` session. Two assertions, both required:
- **Positive observation:** the log contains at least one path with a
  `.mozilla` component. This is expected on every build — `nsXREDirProvider.cpp`
  hardcodes it — and its presence is what proves strace captured real filesystem
  activity from the real binary and that the matcher can see it. An empty or
  unreadable log is a FAILURE, never a pass.
- **Negative:** no line matches the exact path prefix `$HOME/.mozilla/firefox`.
  Match the exact path, anchored — never a bare `.mozilla` substring, which
  would false-fail a correct build.
Its positive control runs the whole layer inside a redirected `HOME` created
with `mktemp -d`, pre-creates a `.mozilla/firefox` directory *inside that
sandbox*, launches with `--profile` pointing into it so the binary genuinely

never create, write or delete anything inside the developer's real
`~/.mozilla` tree. Clean the sandbox with `find <dir> -delete`, not `rm -rf` on
