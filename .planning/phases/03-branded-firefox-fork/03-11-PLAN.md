Close the one remaining Phase 3 gap: Success Criterion 5 / BRAND-06, human-verified
FAILED on 2026-08-22 ("I dont really see a diffrece").

Three root causes were diagnosed and all three are addressed or explicitly
dispositioned here:

1. **`brand.properties` is byte-identical across variants** while `brand.ftl`
   correctly diverges (03-REVIEW.md WR-01). Fixed: dev's `brandFullName` gains
   the suffix, and the brand-full-name identity surface is extended to read the
   properties bundle so the two files can never silently disagree again.
2. **No window title is painted at all.** Both variants draw client-side
   decorations (tabs-in-titlebar), so `MOZ_APP_DISPLAYNAME`/`-brand-full-name`
   never reaches a surface a human can see. Fixed by making the **dev variant
   only** default `browser.tabs.inTitlebar` to 0, through the branding pref file
   D-84 already established as the runtime-defaults mechanism. The dev window
   then gets a real title bar reading `<page> — Sourcerer Dev` while release
   keeps tabs-in-titlebar and shows none — two simultaneous differences (window
   shape, and the title suffix Criterion 5 literally names), zero Gecko patch,
   zero chrome work.
3. **The icon badge was imperceptible** (a few orange pixels at 16-32px).
   Deliberately NOT fixed by regenerating icons. There is no image tooling on
   this host — 03-05 had to hand-decode PNGs via zlib/PNG-filter reconstruction
   — so re-badging is a large fragile diff for a cue that is redundant once the
   title bar cue lands, and Criterion 5 is a disjunction ("title suffix **or**
   icon badge"). Recorded as a deliberate skip, not an oversight: if the human
   re-verification still fails, the icon set becomes the next gap's subject.
