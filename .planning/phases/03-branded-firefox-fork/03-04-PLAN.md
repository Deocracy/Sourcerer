## Shared-state rule for this plan

This plan runs in the same wave as plan `03-03`, which is driving live browser
sessions against `objdir/` and reading `upstream/`. **Nothing in this plan may
mutate `upstream/` or `objdir/`.** Every control and every test in this plan
runs against a `mktemp -d` git fixture, and `scripts/rebase-upstream.sh` is
exercised only in `--dry-run` mode locally. Its first real run is the CI run.

  <name>Task 1: Teach the clean-tree gate to classify expected dirt (D-76)</name>
  <files>scripts/fetch-upstream.sh</files>
  <read_first>
    - `scripts/fetch-upstream.sh` in full — especially the commit-SHA identity check (lines 13-36, and the comment explaining why `git describe --tags --exact-match` is not used: the mirror tags this commit with both `_RELEASE` and `_BUILD1` and describe's tie-break is non-deterministic) and the unconditional dirty-tree hard-fail at lines 42-48, which is the block this task replaces.

  </read_first>
  <action>
Replace the unconditional dirty-tree hard-fail with a classifier. Compute the
**expected-dirt set** as the sorted union of every path appearing on a `+++ b/`
line across `patches/*.patch`. Compute the **actual dirt set** as the sorted set
of paths from `git -C upstream status --porcelain`.

Exactly two states are legal:
- the actual set is **empty** — a pristine tree, the pre-apply state a fresh
  clone is in;
- the actual set **equals** the expected set — a fully applied stack.

Anything else hard-fails, naming the difference in both directions: paths dirty
but not accounted for by the stack (Gecko was modified — the rule CLAUDE.md
makes absolute), and paths the stack claims to touch but which are clean (a
patch silently did not apply — the D-75 failure mode, caught a second time
here). Set equality rather than mere subtraction is what buys the second
direction.

Preserve everything else: the commit-SHA identity logic stays exactly as it is,
the `fetch-upstream: FAIL -- <cause>` stderr convention stays, and every failure
still prints an indented copy-pastable remediation line. For unaccounted dirt
the remediation is the `git -C upstream checkout -- <paths>` form; for a
missing patch it is `scripts/apply-patches.sh`.

Also make the script write the `/sourcerer` line into
`upstream/.git/info/exclude` immediately after a fresh clone, so a
`rm -rf upstream && scripts/fetch-upstream.sh` cycle re-establishes the
exclusion without a manual step. Writing it must be idempotent — do not append
a duplicate line when it is already present.

Add a `--self-test` mode that exercises the classifier without touching the real
`upstream/`: build a `mktemp -d` git repo, drive the classifier through the
pristine state, the fully-applied state, an unaccounted-dirt state and a
missing-patch state, and exit 0 only if the first two passed and the last two
failed with the right message. Clean up with `find <dir> -delete`, never
`rm -rf` on an absolute path.
  </action>
  <verify>
    <automated>bash scripts/fetch-upstream.sh --self-test &amp;&amp; bash scripts/fetch-upstream.sh</automated>
  </verify>
  <acceptance_criteria>

  <name>Task 2: scripts/rebase-upstream.sh — the one documented rebase command</name>
  <files>scripts/rebase-upstream.sh</files>
  <read_first>
    - `scripts/fetch-upstream.sh` as modified by Task 1 — the `TAG` constant, the identity check, and the classifier this script composes.
    - `scripts/apply-patches.sh` — the replay and its post-apply per-patch assertion.
    - `scripts/check-patch-surface.sh` — the guard invoked as the last gate.
    - `toolchain-baseline.txt` — the Phase 1 rustc/cbindgen record PITFALLS #2 says every ESR rebase must re-verify.
    - `.planning/phases/03-branded-firefox-fork/03-CONTEXT.md` § D-74 (upstream/ is disposable, patches/ is the single source of truth) and § D-77 (script now, workflow now, no schedule).
  </read_first>
  <action>
Write `scripts/rebase-upstream.sh` (`set -euo pipefail`, `REPO_ROOT` idiom,
`chmod +x`) taking `--tag <NEW_TAG>` and an optional `--dry-run`.

Real mode, in order:
1. Verify the requested tag exists on the remote with `git ls-remote --tags`,
   failing by name if it does not — cheaper than discovering it after a 1.1 GB
   clone.
2. Remove `upstream/` and re-materialize it at the new tag by delegating to
   `scripts/fetch-upstream.sh` with the tag overridden. `upstream/` is fully
   disposable and gitignored (D-01/D-74); no commit ever lives inside it, so
   there is nothing to preserve.
3. Replay the stack with `scripts/apply-patches.sh`. Its post-apply per-patch
   assertion is what makes a patch upstream has adopted fail loudly by name
   rather than vanish — do not reimplement that logic here, and do not add a
   fallback that continues past a failed patch.
4. Run `scripts/check-patch-surface.sh` as a final gate, so a rebase can never
   quietly widen the patch surface into compiled files.
5. Re-run `scripts/fetch-upstream.sh` and require it to report the
   fully-applied state, which is Task 1's classifier confirming the post-rebase
   tree is exactly the stack and nothing more.
6. Print the toolchain re-verification instruction: PITFALLS #2 requires
   `scripts/toolchain-baseline.sh` output to be diffed against
   `toolchain-baseline.txt` after every ESR rebase, and that step needs the Nix
   Gecko toolchain, so state it as the operator's next command rather than
   pretending it ran.

`--dry-run` performs step 1 and then prints the exact commands steps 2-6 would
run, without removing `upstream/` or applying anything. This is the only mode
that may be run locally while another plan is using the tree.

Every failure follows the `rebase-upstream: FAIL -- <cause>` convention with an
indented remediation line. Do not build a stateful rebase branch inside
`upstream/`: D-74 rejects it, and it can be reconstructed from `patches/` at any
later point if the first real rebase proves it necessary.
  </action>

  </verify>
