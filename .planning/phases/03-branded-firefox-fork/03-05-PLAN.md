<objective>
Ship the second branding variant and the desktop entry: a `release` branding
directory whose display name and icon set differ from `dev`, a `.desktop` file
per variant, and a second full build proving both variants come out of the same
tree with correct, distinguishable identity.

Purpose: BRAND-06 asks that a dev build never be mistaken for a packaged
release. Firefox's own nightly/official pattern — two branding directories
selected by `--with-branding` — is the mechanism the build system is designed
around, and it delivers the display name and the icon badge in one move.

Output: `sourcerer/branding/release/`, two `.desktop` files, and a release build
at `objdir-release/` with the dev build at `objdir/` left intact.
</objective>

## Build cycle budget

This plan spends the phase's **second and last** full `./mach build` (~54
minutes, Task 3), into a **separate objdir**. That separation is what keeps the
budget at two: building release into the existing `objdir/` would leave the
daily-driver dev build destroyed and cost a third full build to restore it.
Disk headroom was measured at 1.3 TB free against a 14 GB objdir, so a second
objdir is affordable. The dev `objdir/` must be byte-untouched by this plan.

<assumption_delta_decision>
The detector fired `pluralization` on this phase's scope. The real transition it
names is D-82: **branding goes from singular to plural.** Until this plan there
was one branding directory and the build treated it as a constant.

- **Primary noun:** the *branding variant*. Identity (`MOZ_APP_DISPLAYNAME`, the
  gtk icon set, and therefore the profile directory) is a property of a variant,
  not of the product.
- **Decision: `promote`.** `--with-branding` becomes a parameter of the build
  (`SOURCERER_BRANDING`, defaulting to `dev`), and `dev` is demoted from "the
  branding" to "one variant". The release variant is not added alongside a still
  primary dev variant — neither is primary; the selector is.
- **Accepted consequence, already recorded in D-82:** because the display names
  differ, dev and release builds do not share a profile, and the Linux icon set
  is generated twice. Both are deliberate, not defects.
- **Invariant worth encoding (and encoded here):** every identity assertion
  reads its expected value from the build's own `objdir*/config.status` rather
  than a literal, so a third variant added later cannot be stored but never
  confirmed. That is what Task 2's `.desktop` assertions and Task 3's comparison
  both do.
</assumption_delta_decision>
