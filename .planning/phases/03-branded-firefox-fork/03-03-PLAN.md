## Build cycle budget

**Zero full builds in this plan.** `pref/firefox-branding.js` is installed via
`JS_PREFERENCE_FILES` (a file install, not a compiled define), so every change
here is a `./mach build faster` — seconds, not 54 minutes. If any change in this
plan appears to require a full rebuild, stop and re-check: it means a compiled
define was touched, which belongs in the patch, which belongs in plan `03-01`.

**Step 1 — `sourcerer/branding/dev/pref/firefox-branding.js`.** Replace the
placeholder with the real set. Every pref key listed in the allowlist's `prefs`
array must appear here with exactly its `expect` value; add the following and
extend the allowlist in the same commit if any is missing from it:

- Blank the GMP manager URL (`media.gmp-manager.url`) to the empty string, and
  leave `media.gmp-manager.allowLocalSources` at its default `true`. This is
  D-86: DRM stays working, because the in-tree Widevine source manifest still
  installs the CDM from Google's host with no Mozilla host involved, and per C-4
  Widevine is genuinely lazy on Linux (`media.eme.enabled` defaults false there),
  so it costs nothing at startup. Do **not** disable
  `media.gmp-widevinecdm.enabled` — it routes to a handler that never fetches.
- Set `media.gmp-gmpopenh264.enabled` to `false` (D-87). This codec is the one
  genuinely unattended download at startup: it is visible and enabled
  unconditionally in the browser's own profile defaults.
- Set `extensions.systemAddon.update.enabled` to `false` (D-87). This kills the
  system-addon callout before the URL is ever read, which is more robust than
  blanking the URL.
- Blank `app.update.url.manual` and `app.update.url.details` to the empty
  string. The unofficial template points both at Mozilla infrastructure; that
  must not be carried forward.
- Disable telemetry submission at the pref layer as defence in depth even though
  the health-report subsystem is compiled out: unified telemetry off, the
  telemetry server blanked, health-report upload off, and the data-submission
  policy off.
- Disable the captive-portal service and blank its canonical detection URL.
- Disable the Normandy/Shield client prefs, even though `MOZ_NORMANDY` is
  compiled out, so a reader of the pref file sees the intent stated.
- Disable Pocket, the discovery pane, sponsored top sites and sponsored
  newtab stories — these are what reach the sponsored-tile and story hosts.
- Leave the geolocation provider and Web Push enabled and untouched: neither is
  an unattended startup callout (both fire only on an explicit site request),
  and disabling them removes real browser capability. Record that reasoning as
  a `reason` on their allowlist entries rather than silently leaving them out.

Keep the three `startup.homepage_*` prefs blank and `devtools.selfxss.count` at
5, as the placeholder already has them. Prefs stay **unlocked** (plain `pref()`,
never `lockPref`) so the developer can flip them while debugging (D-84).
Do **not** add an autoconfig `.cfg` or a `defaults/pref/autoconfig.js` — D-84
rejects that mechanism explicitly: it is privileged JS evaluated at startup
where a typo quits the app before it opens.

**Step 2 — `sourcerer/distribution/policies.json`.** Keep it as small as

policies schema: disable application update, disable telemetry, disable

blanked URL pref in the installed pref surface to a stock Mozilla value, re-runs

file and run the plain layer, which must now pass because Task 1 set every pref

**Layer 2 (filesystem, BRAND-03).** Run the positive control first — the
redirected-`HOME` sandbox launch that forces a real touch of a
`.mozilla/firefox` path inside the sandbox — and confirm the layer goes red.
The control must never create, write or delete anything inside the developer's
real `~/.mozilla` tree; verify that by recording `ls -la ~/.mozilla` (or its

layer against the real `$HOME`, which must report at least one observed
`.mozilla` path component (expected — the path component is hardcoded in the
directory provider on every build) and zero matches for the exact prefix
`$HOME/.mozilla/firefox`.

**Layer 3 (network).** Run the plain layer first to **discover** the real host
set, because the allowlist's job is to disposition what actually happens, not
what was predicted. For every hostname the session resolves:
- if it is already in the allowlist with disposition `allow`, leave it;
- if it is in the allowlist with disposition `deny`, that is a real failure —
  find and fix the pref or build flag that still permits it, rebuild with
  `./mach build faster`, and re-run;
- if it is absent from the allowlist, disposition it explicitly. Every
  non-Mozilla host must be either individually waived with a stated reason or
  turned off (D-85); every Mozilla host other than the Remote Settings carve-out
  must be turned off, not waived (D-83). Do not add an `allow` entry to make a
  check pass — an `allow` entry is a decision that must be defensible on its own
  reason line.
Then run the positive control: it flips one deny-listed pref back on, rebuilds
faster, re-runs the layer, and must report FAILURE naming the host that
reappeared; it then restores the pref and rebuilds faster again.
Finally re-run the plain layer and confirm green.

**Idempotency.** Run `bash scripts/verify-endpoints.sh` twice in a row with no
intervening change and confirm both runs produce the identical verdict and the
identical named-host set. If the second run differs, the first run left state
behind — find it and remove the dependency rather than accepting the difference.

**Record.** In the SUMMARY, list every hostname observed by layer 3, its
