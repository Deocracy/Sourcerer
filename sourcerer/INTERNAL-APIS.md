# Internal APIs Catalogue

D-96/D-97: `sourcerer/shell/SourcererAPI.sys.mjs` is the **only** file in
`sourcerer/` permitted to reach a Firefox internal. Every row below is one
distinct occurrence of a forbidden pattern (`Services.*`, `Cc`/`Ci`/`Cr`/`Cu`,
XPCOM constructors, `AppConstants`, an unqualified `ChromeUtils.import*`) as
enumerated by `scripts/check-internals-boundary.sh`'s own
`FORBIDDEN_PATTERNS` array, run in `--catalogue` mode directly against
`SourcererAPI.sys.mjs` (the one file the default `--quick`/full scan
excludes). The rule is written once in that script; this document is derived
from it, not maintained beside it — `check-internals-boundary.sh --catalogue`
fails on any occurrence with no matching row here, naming the uncatalogued
`file:line`.

One row = one touchpoint + why, the same discipline
`sourcerer/endpoint-allowlist.json` already uses for network hosts.

## Touchpoints

| Internal | File:Line | `SourcererAPI` Method | Purpose | Threat Notes |
|---|---|---|---|---|
| `resource://gre/modules/Subprocess.sys.mjs` + `resource://gre/modules/ctypes.sys.mjs` (`ChromeUtils.defineESModuleGetters`) | `SourcererAPI.sys.mjs:15` | *(module-level lazy import, backs `spawnProcess`/`pathSearch` and, since Phase 5, `signalBarePid`)* | Lazy-imports Firefox's `Subprocess` module (`spawnProcess`/`pathSearch`, launches and locates the Theia backend) and, added by 05-01-PLAN.md Task 2, `ctypes` (`signalBarePid`, opens `libc.so.6` to call `kill(2)` on a pid this process did not itself spawn — the SIDE-04 leftover-reap case, where there is no `Process` object / `proc.kill()` to use). | **Process-spawn row.** The spawned backend runs unprivileged but with the user's own file access. Phase 2's **D-29** already records that `@theia/ai-terminal`'s backend `ShellExecutionServer` calls `spawn(command, [], { shell: true })` with **no permission logic** — all approval machinery is frontend-only — so Theia's AI terminal is an arbitrary-execution surface reachable the moment the page loads. The sidecar's per-launch token gate (see the cookie row below) is the sole guard against reaching that surface from off-host. **Bare-pid-kill row (D-111):** `signalBarePid` is called by `TheiaService._reapLeftover()` only after `readProcessStartTicks` has confirmed the recorded pid's `/proc/<pid>/stat` start-time ticks match the state file's recorded value **exactly** (string equality, no tolerance). A mismatch is never signalled — the operating system has recycled that pid onto an unrelated process, and `_reapLeftover()` returns without calling `signalBarePid` at all. No port-, process-name-, or process-tree-based selection is used anywhere in the reap path; the state file's own recorded pid plus its exact start-time is the only identity this project ever trusts before sending a real signal to a process it did not spawn. |
| `Services.prefs.getStringPref` | `SourcererAPI.sys.mjs:32` | `getStringPref` | Reads a string pref (sidecar config: `nodePath`, `backendMain`), never throwing — returns the caller's fallback on any error. | None — local config read, no externally-controlled input. |
| `Services.prefs.getIntPref` | `SourcererAPI.sys.mjs:44` | `getIntPref` | Reads an int pref (sidecar timeouts/intervals/log-buffer size), never throwing. | None — local config read, no externally-controlled input. |
| `Services.env.get` | `SourcererAPI.sys.mjs:52` | `getEnv` | Reads an environment variable used to help resolve sidecar paths. | None — host-controlled, feeds only `spawnProcess`'s environment, no network input. |
| `Services.cookies.add` | `SourcererAPI.sys.mjs:105` | `setSessionCookie` | Mints the per-launch `SOURCERER_TOKEN` session cookie that gates every plain-HTTP route on the backend (D-99: `secure=false` is deliberate — the sidecar is loopback HTTP, and a secure cookie would never be sent). | **Cookie row.** The token gates HTTP and the WebSocket upgrade, but Phase 2's **D-66** records that the WS origin validator returns `true` when the `Origin` header is absent entirely — so anything that can reach `127.0.0.1:PORT` and omit `Origin` bypasses that check, and the token is the only real barrier left. The token itself is a pure function of the environment (no re-handshake needed across a respawn, D-104), so its secrecy is what stands between a co-resident process and the backend. |
| `Ci.nsICookie.SAMESITE_LAX` | `SourcererAPI.sys.mjs:115` | `setSessionCookie` | `SameSite=Lax` constant applied to the token cookie. **Lax, not Strict:** the shell's one swap is a top-level navigation from `chrome://sourcerer/...` to `http://127.0.0.1:PORT/`, which is cross-site, and Strict withholds the cookie on precisely that navigation — the backend answers the shell's own first request with 403 and Theia never loads. Lax still sends it on that top-level GET while withholding it from cross-site subresources and POSTs. | Same cookie-row note as `SourcererAPI.sys.mjs:105` above (D-66) — this constant is part of the one cookie-mint call. |
| `Ci.nsICookie.SCHEME_HTTP` | `SourcererAPI.sys.mjs:116` | `setSessionCookie` | Cookie-scheme constant permitting the token cookie over plain HTTP, matching D-99's loopback-HTTP rationale. | Same cookie-row note as `SourcererAPI.sys.mjs:105` above (D-66). |
| `Ci.nsICookieValidation.eOK` | `SourcererAPI.sys.mjs:123` | `setSessionCookie` | Compares `add()`'s returned `nsICookieValidation.result` against `eOK` and throws when the cookie was rejected. | Same cookie-row note as `SourcererAPI.sys.mjs:105` above (D-66). `nsICookieManager.add()` reports a rejected cookie by **returning** a validation object rather than throwing, so discarding it turns an unusable token cookie into a silent 403 at the far end of the swap — which is precisely how an expired `aExpiry` went unnoticed through Phase 4. This check is what makes that failure loud. |
| `Cc["@mozilla.org/timer;1"]` / `Ci.nsITimer` | `SourcererAPI.sys.mjs:177` | `sleep` | Platform one-shot timer backing the supervisor's health-loop delay — a `sys.mjs` module's global scope has no `setTimeout`, confirmed against multiple in-tree modules that either import `Timer.sys.mjs` or hand-roll it with `nsITimer`. | None — no externally-controlled input, purely an internal timing primitive. |
| `Ci.nsITimer.TYPE_ONE_SHOT` | `SourcererAPI.sys.mjs:199` | `sleep` | Timer-type constant for the one-shot delay, part of the same `sleep` call. | None — see `SourcererAPI.sys.mjs:177` above. |
| `Services.obs.addObserver` | `SourcererAPI.sys.mjs:240` | `onQuitGranted` | Registers `TheiaService`'s shutdown hook on `quit-application-granted` — the final, non-cancellable quit topic. | **Quit-observer row.** If the browser is force-killed (`SIGKILL`, a crash, `kill -9`) rather than quit normally, this observer never fires and the spawned backend receives no signal at all, leaving an orphaned process. This gap is explicitly out of this phase's scope and is named here rather than discovered later: it is Phase 5's **SIDE-04** (zero orphaned processes after `SIGKILL`, process-group kill semantics plus startup cleanup of leftovers). |
| `Services.obs.removeObserver` | `SourcererAPI.sys.mjs:241` | `onQuitGranted` | Unregisters the quit observer via the unsubscribe function `onQuitGranted` returns. | Same quit-observer note as `SourcererAPI.sys.mjs:240` above (Phase 5 SIDE-04). |
| `Services.obs.notifyObservers` | `SourcererAPI.sys.mjs:264` | `notifyStartupFinished` | Fires `browser-idle-startup-tasks-finished`, the topic Firefox's own chrome fires from `browser/base/content/browser-init.js` once a browser window finishes initializing. The Sourcerer shell is deliberately **not** that chrome, so nothing else in the process ever fires it. | **Automation-reachability row.** WebDriver's `session.new` blocks on this topic (`remote/components/RemoteAgent.sys.mjs`; `remote/webdriver-bidi/WebDriverBiDi.sys.mjs` awaits `browserStartupFinished`). Without it no WebDriver session can ever be created against the shell, so *every* automated check that drives the real binary is unrunnable — the condition that made Phase 4's shell checks look environmentally blocked. Fired once, from the shell's own `DOMContentLoaded`, after the shell has painted; it announces window readiness only and grants no capability. |
| `Cu.getGlobalForObject` | `SourcererAPI.sys.mjs:276` | `createPermanentKey` | Mints a `permanentKey` object in the system global for the shell's one `<browser>`, exactly as `browser/components/tabbrowser/content/tabbrowser.js:2743` does for every tab it creates. Created in the JSM global, not the window's, so the key stays valid if anything outlives the window. | **Automation-reachability row**, same class as `SourcererAPI.sys.mjs:264`. `remote/shared/NavigableManager.sys.mjs:131` returns a **null** context id for any browser lacking a `permanentKey`, so without this the shell's browsing context is enumerable but unaddressable and no WebDriver command can target it. Mints a plain empty object used only as an identity token — it carries no data and grants no capability. |
| `fixupAndLoadURIString` | `SourcererAPI.sys.mjs:293` | `loadURIInBrowser` | Navigates the shell's one content `<browser>` to the Theia backend URL — the single swap SHELL-05 sequences after both readiness sentinels. | **Navigation row.** This is the only navigation the shell ever performs and its target is always the loopback backend the supervisor just health-gated, never externally-supplied input. It previously lived in `sourcerer.js` with a comment saying it stayed there to avoid this file — a real internals touch outside the boundary, uncatalogued, while `check-internals-boundary.sh` reported PASS because its pattern list did not name this API. Both this and `nodePrincipal` are in `FORBIDDEN_PATTERNS` now, so the same class of hole fails the guard instead of passing it. |
| `ownerDocument.nodePrincipal` | `SourcererAPI.sys.mjs:294` | `loadURIInBrowser` | Supplies the triggering principal for that one navigation: the shell is loaded from `chrome://`, so its document principal is the system principal. | Same navigation row as `SourcererAPI.sys.mjs:293` above. Using the system principal is what lets a chrome document initiate the load at all; the load target is fixed by the supervisor, so this does not widen what can be navigated to. |

## Deliberately not touched

| Internal | Reason |
|---|---|
| Firefox's session store (`sessionstore.jsonlz4`, `SessionStore.sys.mjs`) | **D-107:** Phase 4 introduces no persistence of its own — port, PID, token, and the supervisor's log buffer are all per-launch, in-memory state; nothing writes session files, and no dependence on Firefox's SessionStore is added. **D-108:** naming it here, un-touched, keeps the storage ground clean for the future unified SQL store (SEED-001, dormant this milestone), whose first real consumer (the chrome-owned TabModel) is post-4.0. |

## Consistency

Enforced by `scripts/check-internals-boundary.sh --catalogue`, run as the
`internals-catalogue` check in `scripts/verify-phase-04.sh`'s `--quick` set.
It re-derives the occurrence list above straight from
`SourcererAPI.sys.mjs` using the guard script's own `FORBIDDEN_PATTERNS`
enumeration and fails on any occurrence whose `file:line` has no matching
row here — the two can never silently drift apart. `--self-test` proves the
check can go red on both a planted boundary violation and a planted removal
from this document.
